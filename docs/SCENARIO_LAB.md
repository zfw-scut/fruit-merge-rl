# 自定义场景实验室

- 状态：场景编辑、真实物理与 Reward V2 奖励可视化已接通；模型 checkpoint 推理尚未接入
- 用途：用鼠标快速构造极端局面，并在同一局面并行比较21个动作的真实结果
- 入口：`tools/open_scenario_lab.py`

## 当前能力

- 从左侧水果列表按下拿起新水果，保持按下拖入画布，松手释放；画布空白处直接按住放置仍作为快捷方式保留；
- 服务连接时，松手后自动用真实物理把当前水果推进至稳定，并播放真实下落轨迹；
- 鼠标滚轮切换当前或选中水果等级；
- 11 级水果贴图、真实显示半径、危险线、空间网格和 21 个动作锚点；
- 场景撤销与重做，q0～q3 队列编辑，30/120 FPS 评估参数；
- 濒临出界、底层缺口、同级堆积和空白场景预设；
- 重叠与越线几何提示、最多 64 个水果限制；
- 自包含 JSON 导入导出，不依赖外部前端框架或网络资源；
- 真实执行21个动作并显示推荐动作、空间奖励、终局、得分增量和投放后局面；
- 逐个查看 q1～q3 的投放前后21列深度，绿色表示新增空间、红色表示损失空间；
- 服务端使用训练同源的物理和 Reward V2 公式，浏览器不计算演示奖励。

## 交互和视觉原则

场景画布始终是页面视觉中心。左侧只保留编辑工具和水果选择，右侧按“场景设置”和
“评估结果”分离信息，避免同时铺开大量指标。颜色、圆角、半透明表面和控件状态采用
Windows 11 Fluent 方向；危险、重叠和后端未连接使用不同层级提示，不靠大段文字抢占
场景空间。

## 后端边界与请求

前端点击“整理当前场景至稳定”或“评估 21 个动作”时会派发
`daxigua:scenario-request`，其中包含场地、场上水果、q0～q3、物理帧率和投放探针。
服务模式通过 `/api/evaluate` 校验请求，把同一场景复制到21个环境，并分别投放 A0～A20。
30 FPS 使用训练物理档，120 FPS 使用高精度评估档。详细空间诊断只在该请求中产生，
不进入训练 Replay 或训练热路径。

放置和拖动后的自动整理调用 `/api/settle`，不投放 q0、不消费队列，也不增加决策步数。
为保证鼠标交互延迟，自动整理固定使用30 FPS训练物理；用户主动点击整理按钮时仍按页面
当前选择的30/120 FPS执行。接口同时返回按30次/秒采样的真实物理轨迹：30 FPS每帧记录，
120 FPS每4帧记录。浏览器只对相邻真实采样帧做显示插值，不近似计算落点或碰撞结果。

后端会根据水果等级补齐质量、惯量等派生属性；JSON 中的物理半径允许显式覆盖，以便
复现刚投放和合成后的细微半径差异。队列只允许自然生成的1～5级水果，场上水果允许
1～11级，最多64颗。页面继续暴露 `window.daxiguaScenarioLab`，方便后续接入模型动作。

## 使用

```powershell
$env:PYTHONPATH = 'src'
& $python tools\open_scenario_lab.py --serve --device cuda --open
```

无 CUDA 的开发机可使用 `--device cpu`。`--port 0` 会自动选择空闲端口。不传
`--serve` 时只在 `recordings/scenario-lab/index.html` 生成自包含页面，便于编辑、导出
或归档视觉版本；离线页面不会产生评估结果。
