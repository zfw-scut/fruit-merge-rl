# 自定义场景实验室

- 状态：持续实时物理、暂停场景编辑、Reward V2.1 奖励可视化、模型单次推理、辅助动作预测对照与持续决策已接通
- 用途：像游戏一样连续投放水果，也可暂停构造极端局面，并在任一状态快照上并行比较21个动作
- 入口：`tools/open_scenario_lab.py`

## 当前能力

- 运行态可从左侧拖入水果，或在画布按下、水平移动后松手投放；
- 运行态按住任意场上水果会自动临时暂停并进入拖动编辑，松手时先同步场景、再自动恢复物理；
- 运行态右键水果可直接删除，也可先选中后使用 Delete 或右侧删除按钮；
- 运行态可随时切换“放置”和“选择”；两种工具下都可直接按住已有水果进行临时编辑；
- 物理世界持续推进，前一颗水果仍在下落时可立即投放下一颗，不等待稳定或回放；
- 暂停态可放置、拖动、删除和切换场上水果等级，恢复后从当前状态继续物理模拟；
- 鼠标滚轮切换当前或选中水果等级；
- 11 级水果贴图和真实显示半径；危险线、空间网格、21个动作锚点等辅助层可在设置页独立开关；
- 场景撤销与重做，q0～q3 队列编辑，30/120 FPS 评估参数；
- 濒临出界、底层缺口、同级堆积和空白场景预设；
- 重叠与越线几何提示、最多 64 个水果限制；
- 自包含 JSON 导入导出，不依赖外部前端框架或网络资源；
- 真实执行21个动作并显示推荐动作、空间奖励、终局、得分增量和投放后局面；
- 评估结果使用独立静态快照，可在“投放前/投放后”之间切换，不会被后台实时物理状态覆盖；
- 可选查看 q1～q3 的投放前后21列深度，绿色表示新增空间、红色表示损失空间；场景空间评估默认关闭，不与动作效果预测混合显示；
- 服务端使用训练同源的物理和 Reward V2.1 公式，浏览器不计算演示奖励。
- 可加载任一兼容 GNN-DQN checkpoint，对任意手工场景只读输出21个动作的 Q 值、首选投放点与推理耗时；
- 同一场景执行奖励评估后，会直接显示模型首选动作的真实空间奖励和 Reward V2.1 最优动作，模型推理不会自动投放或修改场景。
- 带辅助动作头的 checkpoint 会在稳定场景形成或 q0～q3、场上水果发生变化后自动执行一次推理，并一次返回21个动作的效果预测；切换动作时只读取缓存，不会再次推理；
- 真实评估为每个动作返回与训练监督同语义的物理事实，并显示首次接触位置误差、合成次数、新水果数、q0最终等级和得分增量；
- 顶部主页面只保留刷新模型预测、持续决策、执行验证和动作切换等常用操作；基础画布、动作预测、真实效果、误差线、法向量、概率明细和场景空间评估统一放在齿轮设置页，并保存在浏览器本地设置中；
- 可从任意手工场景启动模型持续决策：连续稳定后 greedy 推理、真实投放、再次等待稳定并循环；
- 持续模式会自然推进 q0～q3，允许暂停/恢复；停止后保留当前局面，不自动重置。

## 交互和视觉原则

场景画布始终是页面视觉中心。左侧只保留编辑工具和水果选择，右侧按“场景设置”和
“评估结果”分离信息，避免同时铺开大量指标。颜色、圆角、半透明表面和控件状态采用
Windows 11 Fluent 方向；危险、重叠和后端未连接使用不同层级提示，不靠大段文字抢占
场景空间。

设置页把可视化分成“基础画布”“辅助动作预测”“场景空间评估”和“信息密度”四组。
实时预测默认开启，场景空间评估默认关闭；关闭空间评估只隐藏空间势能、队列槽位和21列
深度图，不影响辅助动作预测、真实动作效果或场景快照。用户可分别勾选需要的图层，避免
不同诊断语义同时覆盖画布。

## 后端边界与请求

服务内保留一个持久化 Pymunk 世界，以120 FPS固定时步在独立线程推进，
并通过 `/api/live/events` 以60 FPS发布状态。`/api/live/command` 在物理帧边界处接收
投放、按水果 ID 删除、暂停、恢复、清空和载入场景命令；连续投放不依赖“已稳定”条件。
浏览器不再把60 Hz状态包直接当作显示帧，而是在相邻快照之间按
`requestAnimationFrame` 插值；因此物理仍为120 FPS，显示帧率则跟随实际屏幕刷新率。

运行态拖动使用严格串行的临时编辑事务：暂停物理、读取权威场景、拖动、同步修改、
恢复物理。快速点按会走同一条事务但不改变位置；拖动过程中按 Esc 或指针被系统取消时，
会恢复拖动前场景再继续模拟，避免半完成编辑和模式锁死。

前端点击“评估当前探针动作”或“评估 21 个动作”时会派发
`daxigua:scenario-request`，其中包含按下按钮时的场地、水果位置与速度、q0～q3、评估帧率和投放探针。
`/api/evaluate` 把这个状态快照复制到21个环境，分别投放 A0～A20；它不暂停实时世界。
返回的每个动作都包含投放后水果快照 `result_fruits`。前端在“评估结果”页固定显示发起请求时的
投放前局面或选中动作的投放后局面；只有启用“场景空间评估”后才绘制该快照对应的21列空间变化。
后台实时世界仍持续运行；切回“场景设置”即恢复实时画面与交互。
30 FPS 使用训练物理档，120 FPS 使用高精度评估档。详细空间诊断只在该请求中产生，
不进入训练 Replay 或训练热路径。

实时预测启用时，前端会在稳定场景形成后将状态快照提交给 `/api/model/evaluate`；手工编辑、
切换 q0～q3 或载入场景后使用短防抖，实时物理只在再次稳定时触发，并以场景内容键去重。
同一时刻最多存在一个请求；请求期间发生的新变化会在当前请求结束后补一次最新预测。
动作滑杆不属于场景内容变化，因此 A0～A20 切换只重绘本次返回的21组结果。手工“刷新模型
预测”仍可用于强制刷新。后端根据
checkpoint 内冻结的 `ModelConfig` 重建 GNN-DQN，并返回 A0～A20 的 Q 值。若
`action_effect_enabled=true`，同一次共享编码还会返回全部21个动作的辅助效果预测；
前端把训练标签使用的归一化坐标、速度、时间和分数恢复为像素与物理单位。手工场景
没有持续越线帧数，因此模型输入中的 `danger_progress` 固定为0，但仍会根据水果位置提供
`over_danger_line`。该接口只做一次 greedy 推理，不推进物理，也不改变实时世界。

`/api/evaluate` 的 `format_version=4`。每个动作除原有空间奖励和投放后水果外，还包含
`action_effect`：实际合成、q0谱系、首次接触、前三次全局新水果和结局事实。该字段直接来自
已开启 `track_action_effects` 的21环境物理评估，不根据模型预测反推；因此预测与真实可以
独立显示。画布颜色约定为：蓝色虚线为预测首次接触、绿色为真实首次接触、紫/橙分别为
预测/真实新水果、青/黄分别为预测/真实q0最终后代，黄色虚线连接位置误差。

“启动模型持续决策”通过 `/api/model/control` 开关独立控制线程。控制器使用实时状态中的
真实 `danger_progress`，并要求局面按60 Hz发布状态连续稳定8次（等价约0.125秒）后才
允许决策；水果拓扑变化、运动、暂停都会清空稳定累计。模型动作通过 `drop_action` 进入
同一个 Pymunk 世界并自然推进队列。持续模式不会重置手工场景；手工载入、删除、清空或
投放会先停止模型控制，避免模型与用户同时写入物理世界。默认单次启动最多1000次投放，
终局或错误也会自动停止。

后端会根据水果等级补齐质量、惯量等派生属性；JSON 中的物理半径允许显式覆盖，以便
复现刚投放和合成后的细微半径差异。队列只允许自然生成的1～5级水果，场上水果允许
1～11级，最多64颗。页面继续暴露 `window.daxiguaScenarioLab`，方便后续接入模型动作。

## 使用

```powershell
$env:PYTHONPATH = 'src'
& $python tools\open_scenario_lab.py --serve --device cuda `
    --checkpoint runs\cloud_rtx5090_auxiliary_action_feb10ec_seed20260809_24m\checkpoints\final.pt `
    --model-device cuda --open
```

无 CUDA 的开发机可使用 `--device cpu --model-device cpu`。不指定 `--checkpoint` 时，
实时物理和空间奖励仍可使用，但模型倾向按钮会禁用。`--port 0` 会自动选择空闲端口。不传
`--serve` 时只在 `recordings/scenario-lab/index.html` 生成自包含页面，便于编辑、导出
或归档视觉版本；离线页面不会产生评估结果。

旧 checkpoint 仍可加载和查看 Q 值；若其 `action_effect_enabled=false`，辅助动作区域会
明确显示“当前模型没有辅助动作头”，不会伪造预测数据。位置误差用于单场景直观诊断，
不能替代固定评估集上的总体准确率、分位数或校准指标。
