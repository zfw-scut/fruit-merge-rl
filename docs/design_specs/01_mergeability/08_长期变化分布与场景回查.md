# 长期变化分布与场景回查

## 当前状态

- 长期变化量正式统计：**已完成，可作为后续设计证据**；
- 负变化前后场景画廊：**正式采集与本地CPU渲染已完成，待人工逐图复核**；
- 关键投放阈值：**尚未选择，不写入检测器**。

## 指标与数据来源

正式数据来自SAB-128 greedy、当前30 FPS无自由下落加速环境。场景总体可合成值定义为
所有活动水果的`可合成分数 × πr²`之和；变化量只在同一局相邻两次稳定投放之间计算，
终局重置后的首个投放不跨局做差。

正式批次采用2000个CUDA并行环境和2000个批量决策步，共4,000,000条投放记录，其中
3,992,382条变化量有效，覆盖5,622个自然终局和7,622个已启动对局。采集用时564.68秒，
平均吞吐7,083.64条环境投放/秒。完整原始分片和图表保存在
`runs/diagnostics/formal_sab128_env2000_steps2000_20260825_r2/`。

## 已确认的分布事实

| 统计量 | 结果 |
| --- | ---: |
| 正变化比例 | 71.38% |
| 负变化比例 | 27.38% |
| 零变化比例 | 1.24% |
| 有符号变化量中位数 | 1,809.14 |
| 正变化幅度 P50 / P75 / P95 | 3,076.25 / 7,039.66 / 22,172.81 |
| 负变化幅度 P50 / P75 / P95 | 7,147.75 / 20,346.16 / 61,597.65 |

负变化次数少于正变化，但幅度尾部明显更重。局内阶段差异同样明显：1～9次投放的负向
P05约为-945，50次以后约为-23,261至-30,620。后续不能在没有排除或归一化开局阶段的
情况下，直接把一个固定绝对阈值解释成统一严重度。

## 首版负变化分层

画廊先按负变化自身的幅度分位数分成四档，每档抽取64组，共256组：

| 档位 | 幅度范围 | 分布语义 |
| --- | ---: | --- |
| 轻微 | `0 < |Δ| < 7,147.75` | 负变化中的较小50%，用于观察细微变化或度量噪声 |
| 一般 | `7,147.75 ≤ |Δ| < 20,346.16` | 负变化P50～P75 |
| 严重 | `20,346.16 ≤ |Δ| < 61,597.65` | 负变化P75～P95 |
| 极端 | `|Δ| ≥ 61,597.65` | 负变化最重的5% |

这些边界只用于把人工检查材料铺开，不是关键事件阈值，也不代表四档已经具有训练语义。
边界应保持为采集参数，之后可以基于同一快照数据重新合并或调整。

## 场景采集方案

- 重新运行轻量CUDA rollout，因为已有4M标量记录没有保存完整棋盘，无法事后还原图片；
- 每个候选严格保存当前投放前的稳定场景和该投放结束后的稳定场景；
- 只采集有效同局负变化，不采集终局重置边界；终局投放本身仍可保留；
- 使用固定时长rollout和随机优先级蓄水池，在每个档位中均匀抽取，而不是取最先出现的样本；
- 记录环境、episode、局内投放、动作、投放水果、合成事件、得分变化和终局标志；
- 快照只保存绘图和后续回查需要的固定张量，不记录逐物理帧轨迹；
- 快照数据集与图片渲染器分开。以后调整配色、文字或页面布局，不重新运行物理对局。

## 图片语义

每组图片左右并列显示“投放前”和“稳定后”，使用相同的棋盘范围与水果等级配色。水果内部
显示等级、ID和当前可合成分数；填充色继续表达可合成性高低。投放横坐标和投放水果单独标出，
信息区至少显示：

- 负变化档位和精确`Δ`；
- 场景总体值前后变化；
- 局内投放次数、动作、投放等级和水果ID；
- 本次合成数量、游戏得分变化、终局状态；
- 前后水果ID的新增和消失，用于区分结构变化与正常合成替换。

图片用于回答“这种幅度通常对应怎样的一步场景变化”，不能单独证明某次投放对更长期结果的
因果影响。若发现大幅负变化主要由正常合成时面积、ID或单果分数重算引起，应先修订场景总量
或归一化方式，再讨论关键节点。

## 首轮验收

1. 四档各有64个有效且不跨局的样本；
2. 每组投放前后只相差一次真实SAB-128决策；
3. 图片元数据与快照张量中的`Δ`、episode和投放次数一致；
4. 小幅、严重和极端档位从画面上能观察到不同类型的变化，而不是全部由同一种合成事件主导；
5. 若某档大多无法人工解释，先保留原始快照并调整展示或指标，不立即写检测规则。

## 正式场景回查结果

正式回查使用2000个CUDA环境运行1000个批量决策步，共观察2,000,000次投放和2337个
自然终局。随机优先级蓄水池从四档分别观察到的272,997、135,641、107,746和26,806个
候选中各保留64组，最终得到256组不跨局的“一次真实投放前/稳定后”快照。采集耗时
273.17秒，平均7,321.55次环境投放/秒；峰值CUDA保留显存约7.39 GiB。紧凑快照数据集
约4 MiB，本地画廊包含256张成对图片和1张总览图，图片合计约69.70 MiB。

- `runs/diagnostics/mergeability_negative_transitions_sab128_env2000_steps1000_20260825/negative_transitions.pt`；
- `runs/diagnostics/mergeability_negative_transitions_sab128_env2000_steps1000_20260825/gallery/`；

### 合成事件与负变化档位

| 档位 | 任意合成 | 至少2次合成 | 至少4次合成 | 无合成 | 局内投放中位数 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 轻微 | 42 / 64 | 30 / 64 | 2 / 64 | 22 / 64 | 263.0 |
| 一般 | 50 / 64 | 43 / 64 | 7 / 64 | 14 / 64 | 263.5 |
| 严重 | 59 / 64 | 58 / 64 | 29 / 64 | 5 / 64 | 265.5 |
| 极端 | 64 / 64 | 60 / 64 | 44 / 64 | 0 / 64 | 307.5 |
| 合计 | 215 / 256 | 191 / 256 | 82 / 256 | 41 / 256 | — |

只有1个抽样场景在该投放后终局，因此下面的主要混杂因素不是终局重置，而是正常合成和
连锁合成。139 / 256组中，消失水果与新建水果的净贡献绝对值大于持续存在水果的贡献变化，
说明ID替换确实是总体变化的重要来源；同时多数样本的持续水果贡献也在下降，表明一次投放
引起的整图递推重算同样会显著改变旧水果分数。

### 当前最重要的解释边界

“场景总体可合成值显著下降”目前只能解释为**这次投放使可合成性表发生了较大结构变化**，
不能直接解释为“这次投放有害”或“出现关键失败节点”。尤其极端档全部伴随合成，且大多是
多次连锁；成功升级会同时删除多个旧ID、创建一个新ID并改变占用面积，因而可能产生很大的
负变化。严重档中也存在5个无合成样本，这类图片更接近纯几何重排造成的旧水果分数下降，
但数量不足以单独冻结阈值。

因此第一轮材料达到“展示不同幅度对应怎样的一步变化”的目标，同时否定了直接把原始负变化
分位数写成坏事件阈值的做法。下一步先由人工浏览完整画廊，决定是保留总量作为通用结构扰动
信号，还是把无合成重排、正常合成替换和连锁合成拆开分析；在此之前不修改训练或反事实逻辑。
