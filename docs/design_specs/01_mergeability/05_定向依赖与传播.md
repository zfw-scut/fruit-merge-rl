# 定向依赖与传播

- 状态：**第一代 Top-3 定向传播已实现待观察**

## 为什么不传播全部邻居

可合成性要表达最可能的合成链，不需要把局部所有水果都组成反复传播的稠密关系。全邻居传播
不仅增加 CUDA 成本，也会让大量低质量候选通过数量累加影响分数。

因此第一版为每颗目标水果只保留少量最相关依赖。

## 选择顺序

当前暂定使用以下离散优先级：

1. 同级局部伙伴直接成为终点；
2. 没有同级终点时，选择等级差最小的低级候选；
3. 只保留前 K 个候选；
4. 同等级候选过多时需要确定稳定的排序规则，但距离只允许用于选取，不进入贡献分数。

第一代 K 取 3。同等级并列候选只用归一化几何接近程度决定选取顺序；这个距离不进入最终
难度或可合成性分数。

## 无环传播

- 依赖只能从高等级目标指向更低等级候选；
- 同级关系只作为终点，不形成互相递归；
- 低等级基础结果先确定，再逐级计算高等级目标；
- 外部供给可以作为各等级的独立基础来源。

这个方向使传播关系在等级维度上天然无环，不需要运行通用图循环收敛算法。

## GPU 批量约束

第一版实现应保持：

- 固定水果槽和固定 K 的张量形状；
- 邻域筛选、候选排序和逐级传播能够批量运行；
- 不为每个环境返回不同长度的 Python 图对象；
- 不在 GPU 与 CPU 之间逐环境同步；
- 只有人工可视化时才恢复依赖线和说明信息，训练路径不生成绘图数据。

这些是实现边界，不代表当前已经完成性能验证。正式接入大规模 rollout 前仍需要短吞吐对照。

## 近似边界

Top-K 只限制每颗水果用于计算自身最佳潜力的依赖数，不做全局资源独占。相同候选可以暂时
被多个目标引用；如果后续发现这种重复引用造成系统性高估，再单独设计资源冲突修正，不在
第一版引入组合优化。
