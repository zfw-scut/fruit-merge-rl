# Merge Potential 对局数据采集

本工具使用指定checkpoint在当前`TensorVectorSimulator`中执行批量greedy对局，记录每颗
稳定决策状态中可见水果距离下一次参与合成的投放次数`T_merge`。当前默认身份是
`SAB-128 final.pt`、30 FPS、完整逐帧下落、无单局投放上限。

## 数据口径

采集阶段不预先固定可视化窗口，而是保存三张可关联的原始张量表：

- `snapshots`：水果首次进入稳定决策状态以及稀疏周期快照；
- `merge_sources`：每次合成的两个来源水果、发生投放和结果水果；
- `episodes`：自然终局、模拟器截断、显式投放边界或采集停止及终局信息。

水果身份使用`episode_id + fruit_id`。合成产生的新水果具有新的`fruit_id`，视为新的水果
生命周期。投放后立即参与连锁、从未出现在稳定决策状态中的中间水果不会进入快照统计，
但仍保留在合成事件表中。

离线关联后，每个快照只会得到以下三种结果之一：

1. `merged`：之后首次参与合成，并得到正整数`T_merge`；
2. `terminal_unmerged`：直到自然终局仍未合成；
3. `censored`：受到投放边界、模拟器截断或采集停止影响，未来结果未知。

截断未知不会计入终局未合成。生命周期统计只使用每颗水果的首次观察；状态条件统计允许
稀疏重复观察，但离线按同一水果的快照数赋予`1 / N`权重，使每颗水果的总贡献为1。

当前四项核心因素的定义为：空间占用率沿用模拟器圆面积和可玩区域面积之比；高度以水果
圆心到底部的距离除以死亡线到底部的高度，同时保留原始`x/y/radius`和水果顶部高度；
同等级数量记录除自身外的同级水果数；最近同级距离同时保存圆心距离和扣除两颗半径后的
表面间隙，没有同级水果时使用独立缺失标志而不是伪造大距离。

## 云端命令

首次性能试运行建议从512并行环境和至少512局开始，保证实际批量不被总局数缩小：

```bash
PYTHONPATH=src python tools/collect_merge_potential_stats.py collect \
  --output-dir runs/analysis/sab128_merge_potential_pilot \
  --episodes 1024 \
  --parallel-envs 512 \
  --physics-fps 30 \
  --max-drops 0
```

工具默认解析以下`SAB-128`权重，并强制核对SHA-256：

```text
runs/cloud_rtx5090_auxiliary_action_structured_branch_seed20260811_128m/checkpoints/final.pt
fc40b9019c65ecba8502f4334d1418b4f93c0e54e984d42ccc4d0b477bddca07
```

完成采集后再生成标签和统计表：

```bash
PYTHONPATH=src python tools/collect_merge_potential_stats.py summarize \
  runs/analysis/sab128_merge_potential_pilot
```

主要输出包括：

- `analysis/lifecycle_by_level.csv`：各等级最终合成、终局未合成和截断比例；
- `analysis/lifecycle_t_merge_histogram.csv`：已合成水果的逐投放次数分布；
- `analysis/horizon_probabilities_by_level.csv`：可配置时间范围内的合成概率；
- `analysis/factor_relationships_by_level.csv`：占用率、高度、同级数量和最近同级距离；
- `analysis/factor_interactions_by_level.csv`：占用率×最近同级距离、高度×同级数量；
- `analysis/labeled/`：保留原始因素、`T_merge`、结果类型和水果归一化权重的分片表。

CSV是可重新生成的基础统计表，不限制后续可视化。修改时间范围和分箱后可以从原始数据
重新执行`summarize`，建议为不同分析参数指定新的`--output-dir`。

## 性能参数

正式采集前在同一云实例上调整以下参数：

| 参数 | 作用 | 初始值 |
| --- | --- | ---: |
| `--parallel-envs` | 同时运行的CUDA环境数 | 512 |
| `--max-wall-seconds` | 可选采集墙钟边界；在途局记为截断未知 | 0（关闭） |
| `--feature-env-chunk` | 最近同级距离的分块环境数 | 256 |
| `--snapshot-stride` | 第一档周期状态快照间隔 | 8次投放 |
| `--max-snapshots-per-fruit` | 单水果最多状态快照 | 32 |
| `--snapshots-per-scale` | 每记录若干次后把后续间隔扩大一倍 | 4 |
| `--transfer-interval` | GPU结果统一回传间隔 | 8个决策轮次 |
| `--shard-rows` | 单个原始张量表分片规模 | 1,000,000行 |
| `--background-writer` | 是否让磁盘序列化与模拟重叠 | 开启 |
| `--compile-model` | 是否编译greedy Q网络 | 开启 |
| `--autocast-bfloat16` | BF16推理候选开关 | 关闭 |

优先调整环境数、特征分块和回传间隔；只有记录仍明显拖慢模拟时才增大快照间隔。
BF16可能改变接近动作的排序，未完成同seed动作一致性核验前不用于正式统计。
`manifest.json`记录完整参数、模型哈希、物理身份、吞吐、表行数和运行状态。
模型编译和CUDA首次初始化计入单独的预热时间，不混入正式`env_steps_per_second`；清单同时
记录正式采集阶段的峰值已分配与保留显存。

采集清单会同步到Xigua Atlas实时训练页。云端训练遥测API按请求只读取
`runs/analysis/*/manifest.json`摘要，本地门户通过既有8765 SSH转发即可展示当前任务的
完成局数、总体进度、吞吐、快照/合成事件行数、峰值显存和物理身份。该读取不加载原始
张量表，也不会向采集进程发送控制命令；即使未连接普通训练run，只要本机存在规范统计
清单，门户也能单独显示统计卡片。

周期快照采用年龄自适应间隔：每颗水果前期按基础间隔记录，每完成4次周期记录后将间隔
扩大一倍。因此默认32个快照可以覆盖约7000次投放的水果寿命，不会因固定上限只留下长寿
水果的早期状态。

`--max-drops 0`表示真实无上限。若为控制试运行时间设置正数，达到边界的局会被标成
`censored`，不会伪装成自然终局。Ctrl+C时已启动的局也会写为采集停止截断，已落盘分片
保持可分析；后续续采建议使用新的输出目录和不重叠的seed范围。

## 建议样本量

- 512～2,048局：检查身份关联、磁盘规模和云端吞吐，不用于稳定条件结论；
- 4,096局：足以观察主要`T_merge`分布，可作为第一轮探索；
- 20,000局：建议的正式基线，能够支撑按等级和少量条件分箱；
- 50,000局：若需要稳定分析高等级水果的稀有长尾或二维交互，可作为增强档。

二项比例在最保守的50%附近若希望95%区间约为±1个百分点，需要约9,600个近似独立
对象。快照虽多，但有效独立性主要来自水果轨迹和对局；高等级水果每局数量有限，因此正式
规模按对局数而不是按快照行数确定。建议先完成20,000局，再根据各等级的生命周期数量、
截断率和交互格有效权重决定是否扩至50,000局。

云端性能试验可依次尝试512、1536、1792和4096并行环境；每组总局数必须不小于环境数，
并使用独立输出目录。先比较端到端`env_steps_per_second`和峰值显存，再在最优环境数附近
调整`feature-env-chunk=128/256/512`与`transfer-interval=4/8/16`。正式统计参数由该实例的
实测结果决定，不从历史训练吞吐直接推断。

2026-08-17在5号RTX 5090实例完成短时标定后，当前正式20,000局任务采用7,168环境、
`feature-env-chunk=512`和`transfer-interval=16`，输出目录为
`runs/analysis/sab128_merge_potential_20k_20260817`。7,168环境短试测约19,160投放/秒、峰值
保留显存28.46 GiB；这是采集性能观察，不是模型效果结论。任务最终完成20,000个自然终局，
无模拟器截断、投放上限截断或采集停止截断；最长对局3,715次投放。25,852,434条快照、
24,523,728条合成来源事件和同规模标签已经迁回本地同名目录。Xigua Atlas数据分析页已
直接读取五张基础分析表，提供时间尺度、单因素、双因素和原始表格视图；它不覆盖CSV，
解释时仍需保留策略与物理身份。完整部署、校验和迁移记录见`codex/80`，界面实现见
`codex/81`。
