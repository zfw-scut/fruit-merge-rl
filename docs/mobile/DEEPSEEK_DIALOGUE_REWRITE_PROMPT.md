# DeepSeek AI 语录重写提示词

## 使用方式

在 DeepSeek 的同一对话中先发送下面的“总提示词”。等它只回复确认后，再逐个上传
`assets/dialogue/` 中的文本文件，并明确发送：

```text
开始重写这个文件。严格保持原文件行数，只输出重写后的正文。
```

一次只处理一个文件，保存结果前必须检查行数。七个文件的事件含义以
`assets/dialogue/README.md` 为准，不能把合成、得分或失败台词写进尚未发生这些
事件的 `THINKING`、`HESITATING`、`READY` 等类别。

## 总提示词

```text
我补充并校准一下这次的正式需求：

我正在设计《合成大西瓜 AI 版》的 AI 语录。游戏包含“玩家挑战 AI”和“AI 自行演示”两种模式，AI 会在思考、犹豫、决定落点、合成得分、意外连锁、局面危险等时刻，以随机间隔弹出一句内心话。

现有文本最大的问题不是“不够可爱”，而是像批量文案：句式太整齐、措辞太完整、经常自我总结，读起来生硬，没有真人玩游戏时随口嘀咕、临时改主意、跟水果说话的感觉。

重写目标：
1. 像一个真实、聪明、稍微有点小戏精的年轻人在边玩边碎碎念；自然口语，可以有停顿、改口、半句话、拟声词和偶尔的小吐槽。
2. 可爱、生动、俏皮，但不要低幼、撒娇过度、网红广告腔或刻意卖萌。
3. 不要大量套用同一个句式换词；每句必须是完整独立创作，不使用随机拼接模板。
4. 每句话单独一行，不加编号、引号、分类标题或解释；保持非空且不超过 24 个 Unicode 字符，允许“嗯。”“行。”等短反应。
5. 必须严格保持原文件的条数，并严格符合对应情绪和触发场景，不能提前声称已经合成、得分或失败。重复原句可以保留为抽取权重，不要擅自去重或纠错。

我接下来会依次发送现有的 txt 文本文件。请先只确认你可以接收和理解，不要马上开始生成；等我明确说“开始重写这个文件”后，再按该文件原有行数一次性完整重写。可以吗？
```

## 验收重点

- 不是“状态播报”，而是短促、自然的即时念头；
- 允许口语省略、停顿和轻微改口，但不能变成难以理解的乱码；
- 不要批量使用“这波、稳住、拿下、安排、计划、执行”等模板化词汇；
- 不要连续感叹号、过量波浪号、网络烂梗或刻意装幼；
- 不要为了凑数量机械地只替换水果名、语气词或句尾符号；用户明确提供的重复原句
  仍须原样保留；
- DeepSeek 的结果仍须通过本项目行数、非空、长度上限、字形和事件语义门禁后才能
  写入 APK。
