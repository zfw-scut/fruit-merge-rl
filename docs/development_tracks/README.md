# 阶段开发轨迹

这个目录专门记录一段方案是怎么一路走过来的：最初想解决什么、需求为什么改变、做过
哪些尝试、哪里被实际结果推翻，以及最后有哪些东西值得留下。

它和其他文档目录的分工如下：

- `docs/design_specs/`保存正在讨论和准备实现的当前方案，回答“接下来按什么规格做”；
- `docs/codex/`按日期记录一次实现改了什么，适合查事实和提交边界；
- `docs/model_evaluations/`保存正式模型身份、指标和证据边界；
- `docs/development_tracks/`按完整开发阶段讲清楚“为什么”，适合后续 Agent 和开发者接手；
- 当前代码、配置和测试仍然拥有最高权威，阶段总结不能覆盖后来的实现事实。

## 目录约定

每个具体阶段都使用`NN_short_topic`命名，例如：

```text
development_tracks/
├─ README.md
└─ 01_pair_risk_to_blockage/
   ├─ README.md
   ├─ 01_问题从哪里来.md
   ├─ 02_一次主要尝试.md
   └─ ...
```

- 开头两位编号只表示本目录中的阅读顺序，不等于`docs/codex/`编号或模型版本；
- 每个阶段必须有自己的`README.md`，先给出结论、状态和阅读路线；
- 一段经历拆成多个主题文件，不把需求、实现、评估和经验全塞进一篇长文；
- 历史方案保留当时语境，但阶段首页必须明确它现在是继续、暂停还是弃用；
- 只在一段工作已经出现明显需求演化或决策价值时建立阶段目录，不为每个小修复建档。
