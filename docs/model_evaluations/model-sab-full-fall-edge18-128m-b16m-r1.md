## 2. 最终4096局评估

最终评估使用30 FPS、greedy、固定seed基数42,000,000以及1000投放评估观察上限。该上限
只属于评估协议，不是训练上限。

| 64水果容量终止 | 0局 |

`【事实】` 4096局最终评估均分为6688.94；周期512局评估从8M的3733.26提高到120M的
6688.02，128M周期点为6498.43。曲线说明本次训练已形成明显学习过程，但周期评估波动和
单训练seed都不允许把局部最高点解释为稳定提升。

`【边界】` 训练期间的“准确里程碑”使用120 FPS评估，因此`best.pt`对应96.001536M，
其512局120 FPS均分为5577.17；`latest.pt`与不可变`transition_128000000.pt`对应完整训练
终点。当前只完成最终4096局30 FPS评估，不能用96M的512局120 FPS结果裁决最终权重在
120 FPS下的排序。

`【边界】` 该模型相对历史SAB-128、SAB-FF120同时改变了随机初始化、物理身份、边输入、
训练预算和评估协议。6688.94只能登记为当前新基线的独立结果，不能直接归因于取消快进、
新增边属性或旁路中的任意单项，也不能由单seed证明可复现优势。

## 4. 当前结论

- `【决策】` 将该run登记为当前完整逐帧、18维边、从零128M训练的新基线证据。
- `【决策】` 保留`best.pt`、`latest.pt`和128M里程碑三种语义，不在缺少最终120 FPS正式
  评估时擅自选定唯一部署权重。
- `【建议】` 若下一步需要确定正式部署checkpoint，优先在云端对96M `best.pt`与128M
  里程碑使用相同4096 seed补做30/120 FPS成对评估；这属于后续评估，不在本次迁移中运行。
