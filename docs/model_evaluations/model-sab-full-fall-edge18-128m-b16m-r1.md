`【事实】` 4096局最终评估均分为6688.94；周期512局评估从8M的3733.26提高到120M的
6688.02，128M周期点为6498.43。曲线说明本次训练已形成明显学习过程，但周期评估波动和
单训练seed都不允许把局部最高点解释为稳定提升。

`【边界】` 训练期间的“准确里程碑”使用120 FPS评估，因此`best.pt`对应96.001536M，
其512局120 FPS均分为5577.17；`latest.pt`与不可变`transition_128000000.pt`对应完整训练
终点。当前只完成最终4096局30 FPS评估，不能用96M的512局120 FPS结果裁决最终权重在
120 FPS下的排序。

`【边界】` 该模型不能与SAB-128、SAB-FF120的历史分数直接排序，因为物理和评估身份不
一致；2.1节另用当前V4协议复评SAB-128后才建立当前环境排序。该排序仍不能直接归因于
取消快进、新增边属性或旁路中的任意单项，也不能由单训练seed证明可复现优势。

## 2.1 SAB-128在当前物理下的同seed复评

为消除旧7161.42分所属物理协议与当前环境不一致的问题，在8号RTX 5090实例使用同一代码
`41b9680`重新评估登记的SAB-128 `final.pt`。旧14维物理边权重通过现有兼容入口在加载时
补四列零；五层`edge_encoder`与`edge_gate`共10个张量逐一断言新增列全零，原checkpoint
保持不变。两组均使用V4完整逐帧物理、30 FPS、4096个相同顺序seed和1000投放观察上限。

| 指标 | SAB-128当前物理复评 | `SAB-FF30-E18` | 新基线变化 |
| --- | ---: | ---: | ---: |
| 局均分 | 6430.51 | **6688.94** | **+258.43（+4.02%）** |
| 中位分 | 4754.5 | **5123.5** | **+369.0（+7.76%）** |
| 标准差 | 2904.18 | **2822.50** | -81.68 |
| P90 / P95 | 11280.5 / 11411.75 | **11295 / 11420.5** | +14.5 / +8.75 |
| 局均投放 / 合成 | 588.29 / 563.12 | **611.58 / 585.01** | +23.28 / +21.89 |
| 合成 / 投放 | **95.72%** | 95.66% | -0.07个百分点 |
| 平均最高等级 | **10.8809** | 10.8784 | -0.0024 |
| L11生成 | **96.75%** | 96.51% | -0.24个百分点 |
| L11消除 | 45.53% | **46.00%** | +0.46个百分点 |
| 达到1000投放观察上限 | 686局 | **737局** | +51局 |
| 平均终局水果数 | **24.51** | 25.90 | +1.39 |
| 危险投放率 | **4.68%** | 5.70% | +1.02个百分点 |

`【事实】` 逐局分差按“新基线减SAB-128”计算为+258.43分，20,000次成对bootstrap 95%
区间为`[+134.57,+380.87]`；新基线逐局胜率55.35%，SAB-128胜率44.58%，平局0.07%。
区间不含0，因此固定这组4096 seed时，新基线在当前物理下的均分优势不是评估抽样波动。

`【观察】` 两者高分尾部和L11生成率几乎相同，主要差异来自新基线更多对局延伸到较长局，
从而提高均分、中位分、投放和合成。代价是危险投放率、终局水果数略高，且单位投放合成率
没有改善；不能把结果描述成所有局面整理指标都更好。

`【结论边界】` 这次复评修正了跨物理直接比较造成的错误印象，确认新基线在当前运行环境
中优于SAB-128。但模型之间仍同时存在训练seed、旁路预算和18维边是否经过训练等差异，
所以不能从+258.43分中拆出新增边属性或取消快进的单项因果贡献。

## 4. 当前结论

- `【决策】` 将该run登记为当前完整逐帧、18维边、从零128M训练的新基线证据。
- `【决策】` 当前V4物理下使用新基线而非SAB-128作为效果基准；旧7161.42分只保留为旧
  评估协议事实，不再用于判断当前环境下的模型排序。
- `【决策】` 保留`best.pt`、`latest.pt`和128M里程碑三种语义，不在缺少最终120 FPS正式
  评估时擅自选定唯一部署权重。
- `【建议】` 若下一步需要确定正式部署checkpoint，优先在云端对96M `best.pt`与128M
  里程碑使用相同4096 seed补做30/120 FPS成对评估；这属于后续评估，不在本次迁移中运行。
