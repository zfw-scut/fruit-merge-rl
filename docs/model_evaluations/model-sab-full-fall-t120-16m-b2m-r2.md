实质改善。

## 3. 训练过程与因果边界

`【事实】` 旁路run实际完成全部2,097,152条旁路transition和524,288个来源状态；最后一条
训练记录中旁路样本占比为11.111%，旁路DQN loss为0.04036、旁路辅助总loss为0.13746。
所以本次低分不是“旁路没有开启”或“旁路预算未执行”。这些loss只证明联合更新存在，不代表
辅助预测准确或策略提升。

`【事实】` 训练日志按窗口聚合后，旁路辅助总loss从8.3M～9M的0.13748降至15M～16M的
0.12864；同期主轨迹辅助总loss从0.14567降至0.10790，而旁路DQN loss从0.04540升到
0.05060。辅助loss有小幅下降，但速度明显弱于主轨迹，且最终游戏分数没有提高；这与训练时
观察到的“辅助预测效果弱、提升趋势不明显”一致，但没有固定离线标签集，仍不能把loss直接
换算为预测准确率。

`【事实】` 无旁路run的512局120 FPS周期评估在8M达到6384.21，12M为6129.50，16M为
6361.65；旁路run在12M达到6611.95，16M为6172.40。旁路版`best.pt`因此保存在12M，
但它没有云端4096局终局索引，不能用一次512局最高值替代正式最终比较。

`【边界】` 旁路run从无旁路run的精确8M checkpoint恢复了模型和优化器，但主Replay重新
预热，旁路Replay从新样本重建；无旁路run则连续训练到16M。两组还使用不同代码提交，
不过提交间唯一代码差异是新增旁路TOML。因主Replay恢复边界不同，本实验比较的是
“8M恢复并加入2.097M旁路”的完整流程与“连续无旁路训练”，不是只改变旁路loss的单因素
消融，不能把约1.6%～2.0%的差距全部归因于旁路样本。

`【边界】` 两组只有一个训练seed；固定4096评估seed和成对区间不能覆盖训练随机性。当前
索引只记录游戏结果与事件，没有固定离线辅助标签集上的预测准确率或校准误差，不能由游戏
分数反推某个辅助头是否变好。

## 4. 决策

- `【决策】` 不把旁路版`final.pt`升级为完整逐帧物理的代表模型；当前保留无旁路
  `SAB-FF120 final.pt`作为本物理身份的正式对照。
- `【决策】` 旁路版`best.pt`作为待核验checkpoint保留。若需要判断12M峰值是否真实，只能
  在云端按相同4096 seed补做30/120 FPS评估；不得在性能明显不足的本机重新评估。
- `【建议】` 若继续检验旁路净贡献，应从同一8M checkpoint同时启动“恢复但旁路关闭”和
  “恢复且旁路开启”两组，统一Replay重建、代码提交、评估点和训练seed；否则仍无法隔离
  resume边界与旁路本身。

训练失败；接力日志、固定8M checkpoint哈希和目标PID已经随归档迁回。
