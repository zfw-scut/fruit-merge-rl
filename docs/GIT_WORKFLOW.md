# Git 工作流与提交规范

本文是本仓库的 Git 管理规范。它适用于人工开发、Codex 和其他自动化 agent。

## 分支约定

- 当前持续开发主线为 `codex/work-1`。
- `main` 保留为稳定基线；需要同步、合并或改写两条分支时，先确认它们的祖先关系。
- 不提交本地密钥、云服务器密码、训练大文件、构建缓存或 `runs/` 运行目录。

## 提交语言

- 所有新提交的标题和正文统一使用简体中文。
- 标题直接使用清晰的中文动宾短语概括结果，不使用 `feat:`、`fix:`、`docs:` 等
  英文类型前缀。
- `AI`、`Android`、`CUDA`、`PyTorch`、类名、函数名、文件名、命令和配置值等
  无法自然翻译或翻译后会失真的技术标识可以保留原文。
- 合并提交使用“合并分支……”或“合并拉取请求……”等中文说明；需要填写正文时，
  正文同样使用中文。

示例：

```text
新增大厅自动存档和 AI 游戏模式
修复局部 Shapley 多进程文件描述符泄漏
记录 250K 正式训练恢复
```

不再使用：

```text
feat: add autosave
fix: repair crash
docs: update runbook
```

## 提交前检查

1. 使用 `git status` 和 `git diff` 确认只包含本次任务相关修改。
2. 只暂存确认过的文件，不覆盖用户尚未提交的其他工作。
3. 根据改动风险运行相关测试、构建或静态检查，并在修改记录中写明结果。
4. 涉及较大功能、结构、兼容性或运行流程变化时，按 `docs/codex/RULES.md`
   新增一条 Codex 修改记录，并同步维护项目文件索引。

## 历史改写与强制推送

- 改写历史前必须确认工作区干净，创建本地备份标签，并保存关键的新旧提交映射。
- 同一祖先链上的长期分支应一起改写和验证，避免形成没有共同祖先的两套历史。
- 必须逐提交验证文件树、父节点顺序、作者、提交者和时间戳；还要核对提交数、
  合并节点、分支祖先关系和最终差异。
- 历史训练记录中的旧提交号和含旧短哈希的 `runs/` 路径是实际产物身份，不能
  机械替换或重命名；需要关联新历史时，应同时注明“重写后”和“重写前”标识。
- 未经用户明确确认，不得把改写后的历史推送到远程。
- 获得确认后只使用带预期旧提交保护的 `git push --force-with-lease`，禁止使用
  裸 `--force`；如果同时改写了 `main` 和 `codex/work-1`，两条远程分支必须一起更新。
- 强制推送后，应提醒其他克隆重新获取或重建本地分支，旧拉取请求和提交链接也可能
  需要重新关联。
