# Git 工作流与提交规范

## 分支边界

- 当前 Reward V2 开发分支为 `reward-v2`，基线来源分支为 `codex/accelerated-v1`。
- 废弃的第一版场景实验室保存在 `archive/reward-v2-first-scenario-lab`，只用于历史审计，
  不继续开发或合并其实现。
- `scenario-lab-realtime` 已并入并更名为正式 `reward-v2` 主线；第一轮云端训练版本固定为
  `model-reward-v2-r1` 标签。
- 当前分支通过独立 worktree 开发，不要在原项目工作树中强行切换该分支。
- 原来的 `codex/work-1` 保留完整训练历史和 Android 成品，不向本分支整批合并。
- 从旧历史迁移内容时使用文件级白名单，并重新核对依赖；不直接 cherry-pick 大型功能提交。

## 提交语言

- 所有提交标题和正文使用简体中文。
- 标题使用清晰的中文动宾短语，不添加 `feat:`、`fix:` 等英文类型前缀。
- 文件名、命令、类名以及 AI、CUDA、PyTorch 等必要技术标识可以保留原文。

## 最小化原则

- 只提交当前已经确认需要的代码和文档。
- 不为尚未确认的模型、训练、模拟或性能方案提前增加占位实现。
- 新增依赖前必须说明用途；不提交未被实际代码使用的依赖。
- 不提交密钥、服务器密码、模型权重、训练大文件、构建缓存或 `runs/`。
- 云服务器连接凭据统一登记在 `docs/CLOUD_SERVER_LOCAL.md`（该文件已在 `.gitignore`
  中忽略，只保存本机、不进入 Git 历史）；任何服务器密码都不得写入其它会被提交的文件。

## 提交前检查

1. 使用 `git status` 和 `git diff` 确认改动范围。
2. 只暂存当前任务相关文件。
3. 运行与保留能力匹配的最小测试。
4. 结构或公共契约发生变化时，按 `docs/codex/RULES.md` 添加修改记录。

## 历史与远程操作

- 未经用户明确确认，不改写历史、不强制推送、不删除远程分支。
- 推送前确认目标分支和 upstream，避免覆盖原项目开发线。
- 每次成功创建本地提交后，默认立即普通推送当前分支；首次推送使用同名远程分支并
  设置 upstream。只有用户明确要求“仅本地提交”时才跳过推送。
- 默认远程为当前仓库已经配置的 `origin`；不得为了完成默认推送擅自新增或更换远程。
- 远程不可达、认证失败或远程包含不能快进的更新时，保留本地提交并报告原因；禁止
  自动强制推送、改写历史或覆盖远程提交。
