# 完善默认远程推送规则

## 修改原因

项目采用本地开发、云端训练和多工作树协作，需要避免本地提交长期未同步到远程。
因此将“提交后默认推送”明确为项目级 Git 管理规则。

## 规则变化

- 每次创建本地提交后，默认普通推送到当前分支的同名远程分支；
- 首次推送同时设置 upstream；
- 用户明确要求仅本地提交时可以跳过推送；
- 默认推送不授权强制推送、历史改写、远程覆盖或擅自更换远程；
- 认证、网络或非快进冲突发生时保留本地提交并报告，不自动破坏远程历史。

同时把 conda `python-torch` 默认环境要求纳入 `AGENTS.md` 的正式提交记录。

## 主要文件

- `AGENTS.md`
- `docs/GIT_WORKFLOW.md`

## 验证

- 使用 `git diff --check` 检查规则文档；
- 推送前核对当前分支、upstream 和 `origin` 地址；
- 使用普通推送同步已有开发分支，不执行 force push。
