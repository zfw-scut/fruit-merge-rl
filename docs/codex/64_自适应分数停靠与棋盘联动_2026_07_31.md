# 自适应分数停靠与棋盘联动

## 修改原因

开局水果集中在画面底部，玩家却必须把视线移到顶部才能确认分数；当水果堆升高后，
把分数固定在底部又会遮挡最需要观察的危险区域。直接在 `50%` 高度翻转会被弹跳
水果和临界堆高反复触发，完整分数卡穿过棋盘也会干扰观察。

## 最终交互

- 新局和低堆局面将分数卡停靠在底部，顶部信息栏压缩，棋盘与水果的视觉位置向上
  平移 `66px`，补齐顶部腾出的空间。
- 稳定水果堆连续超过可玩高度 `56%` 约 `0.65s` 后，分数卡切回顶部，棋盘同步
  复位；连续低于 `44%` 约 `1.10s` 才允许回到底部。
- 换位后至少驻留 `3s`。处在 `44%～56%` 中性带不会积累新切换，也不会取消已经
  确认但因表现繁忙而暂缓的意图。
- 分数卡采用上下两个固定停靠位交叉淡入，并带轻微缩放；棋盘使用 `0.62s`
  quintic smootherstep 连续位移。这样移动方向清楚，但不会让大块不透明卡片横穿
  水果区。
- 玩家拖动、控件操作、合成、浮分、分值吸入或计分脉冲期间不会开始新动画；
  已经确认的换位在表现结束后自动兑现。若玩家在动画途中按住水果，当前动画帧会
  冻结到松手，保证按下和抬手使用同一触控坐标；结算时只收尾已开始的动画，不会
  再产生新换位意图。
- 实时高度只统计年龄至少 12 帧且 Box2D 已稳定的水果。新投水果经过生成线时不会
  把分数卡误推到顶部；读档同样只读取快照中的稳定水果，没有稳定样本时停靠底部，
  避免恰好保存于下落途中时错误吸附到顶部。
- 挑战 AI 取玩家与 AI 两个场景的最大堆高。切换红/蓝前景不会导致 HUD 跟着切换，
  任一方进入高堆危险区时底部也不会被卡片遮挡。

## 坐标与规则边界

棋盘位移只存在于 libGDX 表现坐标。Box2D 水果位置、生成线、地板、危险规则、
模型图输入、21 个动作坐标和存档快照都保持原值。触控入口把相同视觉偏移应用到
可拖动上下界，底部分数卡自身会消费触摸，不能成为隐藏投放区。

合成爆浆、冲击环和分值弹出先按棋盘坐标平移；开始吸入后的分值、轨迹粒子和分数
冲击改为屏幕坐标，目标取当前停靠位。换位在这些效果存在时被阻塞，因此一次分值
序列不会在飞行中途更换目标。

## 实现与验证

- `AdaptiveScoreLayoutController` 是纯 Java 状态机，不依赖 libGDX 或 Box2D；
- `FruitMergeApplication` 负责稳定堆高采样、双场景聚合、绘制/触控坐标映射和
  效果坐标空间；
- Windows 共享渲染器新增 `score-low` 与 `score-high` 固定页面；
- 单元测试覆盖迟滞、确认时间、最短驻留、阻塞兑现、反向证据、动画端点与坏输入；
- `:core:test` 全量通过，并使用真实共享渲染器检查两个停靠位。

本次不改变训练模型、奖励、ONNX 推理、物理参数、游戏得分或存档 schema。
