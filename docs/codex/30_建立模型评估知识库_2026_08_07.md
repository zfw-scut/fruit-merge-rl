# 建立模型评估知识库

## 修改原因

当前训练原始数据集中在本机 `runs/`，模型设计位于 `docs/model/`，开发记录位于
`docs/codex/`，但没有统一位置告诉后续 Agent 各代模型实际表现、已确认不足和原因假设。
这容易让后续迭代只看到实现规格或训练成功，而忽略策略效果退化和证据边界。

## 主要修改

- 新增 `docs/model_evaluations/` 作为当前模型评估的统一入口；
- 为 `baseline-r1` 和 `reward-v2-r1` 建立首版证据报告；
- 建立跨代比较矩阵和新报告模板；
- 使用 `【事实】`、`【观察】`、`【假设】`、`【决策】` 分离证据层级；
- 将评估知识库加入 `AGENTS.md` 的模型、奖励和训练任务必读规则；
- 更新模型状态总览和两份专项设计文档，移除云端训练仍“等待执行”的过期描述。

## 首次归档结论

- Reward V2 的成对热路径吞吐约为分数奖励的99.47%，奖励计算性能门禁通过；
- Reward V2 最终30 FPS局均分较基线低23.00%，120 FPS低24.36%；
- Reward V2 最终窗口正奖励率约98.03%，补偿均值显著高于原始空间损失；
- 补偿过强和静态空间代理与合成目标错位记录为待验证假设，不写成已证明根因；
- `baseline-r1` 继续作为效果与性能基准，Reward V2 R1保留为失败实验样本。

## 旧分支审计

按项目规则只读审计了 `codex/work-1` 的旧训练 readiness、Reward V2记录和250K运行手册。
保留“链路能运行不等于策略变好”“不同 shaped reward 不直接比较”“正式训练产物必须带
代码与配置身份”三项原则；不迁移旧训练入口、状态分析器、归因管线或旧报告目录。
