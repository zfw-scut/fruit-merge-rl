# 删除逐水果运动学静止修正

## 修改原因

Tensor/CUDA 模拟器曾按水果记录连续低位移帧，并在达到阈值后把线速度清零。该机制原本用于
消除固定迭代碰撞求解器在密集堆叠中的残余速度，但无法区分“仍受支撑”和“刚失去支撑”。
失去支撑后的首帧重力位移低于释放阈值时，线速度会被每帧重复清零，造成悬空慢速下沉，
并可能在水果尚未落地时满足稳定判定。下一次投放重置计数后运动才恢复。

针对当前 CUDA Kernel 的复现中，问题水果失去支撑后每帧只下移约 0.125 px，160 帧后仍
离地约 59.93 px，却已经满足连续 15 帧稳定判定。清除计数的对照水果正常加速并落地。

## 删除与新增

- 从 `SimulatorConfig` 删除 `kinematic_rest_frames`、
  `kinematic_rest_displacement_epsilon` 和派生速度阈值；
- 从 CPU Tensor 完整投放与实时增量路径删除帧首位置记录、逐水果静止计数和速度归零；
- 从 CUDA C++/Kernel ABI 删除对应缓冲、参数、本地数组、逐帧扫描及计数写回；
- 保留真正用于决策边界的全环境连续稳定帧计数；
- 删除 benchmark 中已经失效的运动学静止参数，历史结果文件和旧记录保持不变；
- 新物理身份为 `tensor_cuda_v2_no_kinematic_rest`。新 checkpoint 和 run identity 都记录
  该身份；完整 `resume` 拒绝旧物理域，旧 checkpoint 只能通过 weights-only 进入新 run；
- replay plan 同样要求物理身份一致，避免用旧物理轨迹复跑当前模拟器。

本次没有同时修改稳定速度、稳定角速度、稳定帧数、阻尼、求解迭代、合成初速度和等待预算。
删除后重新出现的残余速度与等待超时应单独评估，不能再用逐水果速度钳制掩盖。

## 验证

- CUDA 扩展按收缩后的 ABI 在本机 RTX 4070 Laptop GPU 上重新编译成功；
- `tests.test_vector_simulator`：29 项通过；
- 场景实验室、RL 基线与动作效果学习：58 项通过；
- 新增 CPU/CUDA 回归验证无支撑水果连续三帧持续加速，且同次投放中支撑消失后不会误判稳定；
- 复跑原悬空场景：前三帧向下速度约 15.52、30.52、45.52 px/s，约 40 帧到达地面附近，
  最终只在地面完成稳定判定；
- 256 环境 × 20 次投放 CUDA 随机短测状态有限，5120 次投放中 24 次等待超时，约 0.47%。
  该短测只作为实现冒烟与超时观察，不代表正式训练分布或策略效果。

后续 `codex/69` 进一步证明：相同 30 FPS 且关闭自由落体快进时，训练完整步与场景实验室
逐帧入口逐位一致；训练默认的自由落体快进会改变首次接触状态和长期轨迹，不是等价优化。
