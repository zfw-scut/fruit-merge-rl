# 新增云端基础训练产物同步工具

## 修改原因

5k/10k 云端验收时只人工复制了部分 CSV/JSON，10k 的两张训练曲线和
`attribution_warmup.json` 没有同步到本地。直接复制整个 run 又会误下载约 GiB 级
checkpoint 和 ReplayBuffer，因此需要一个可重复、安全且有明确轻重边界的同步入口。

## 主要修改

- 新增 `tools/sync_cloud_training_artifacts.py`：
  - 通过一次只读 SSH 连接在远端生成内存 tar 流，不创建远端临时文件；
  - 只选择固定白名单内的配置、两份指标 CSV、归因/resume/failure JSON 和两张
    标准训练图；
  - 明确排除 checkpoint、ReplayBuffer、冷段和日志；
  - 默认支持训练中增量同步，阶段结束可用 `--require-complete` 强制要求配置、
    两份指标 CSV、warmup、两个 shutdown、两张标准训练图，并按最新恢复配置核对
    目标 update、拒绝活动 failure；
  - 自动探测非交互 SSH 环境中的系统 Python 和常见 `python-torch` Conda 路径；
  - 本地拒绝绝对路径、`..`、Windows 反斜杠/驱动器穿越、保留名、大小写冲突、
    链接、设备文件、白名单外成员和超限归档；
  - 校验 JSON、CSV 表头/数据行及 PNG signature/IEND，全部通过后构建含新
    manifest 的完整替换目录，再以目录事务切换；
  - Windows 上替换目录直接建在目标父目录下以继承工作区 ACL，不把
    `TemporaryDirectory` 的受保护 ACL 搬到最终目标；
  - 远端不能覆盖本地 readiness/resource/status 等旁路证据，旧的受管 optional
    不会残留，manifest 不含凭据；
  - SSH 传输有总超时、归档大小和 stderr 大小上限。
- 新增专项单元测试，覆盖命令引用、无密码参数、安全解包、白名单、严格完整模式、
  校验失败不覆盖、幂等同步和无关证据保留。
- 更新项目文件索引和第一次 500k runbook，记录训练中与阶段结束两种同步命令、
  认证边界和查看方式。

使用完整模式从云端
`runs/dqn_causal_calibration_10k/` 同步到本地
`runs/cloud_evidence/10k/`，共 8 个文件、902177 bytes，`missing_optional=[]`。
新增或补齐：

- `attribution_warmup.json`：3085 bytes；
- `plots/training_curves.png`：340040 bytes；
- `plots/reward_breakdown_curves.png`：253711 bytes；
- 云端同源的 config、metrics、episode metrics 和两个 shutdown JSON。

目标目录原有 readiness、resource/cgroup summary 和 stage status 均被保留。
两张 PNG 已通过完整性检查和实际解码查看。同步产物位于被 `.gitignore` 排除的
`runs/`，不会把训练数据误提交到 Git。

## 验证方式

```text
python -m unittest tests.test_sync_cloud_training_artifacts -v
11 tests, OK

python -m py_compile \
  tools/sync_cloud_training_artifacts.py \
  tests/test_sync_cloud_training_artifacts.py

conda run --no-capture-output -n python-torch \
  python -m unittest discover -s tests
323 tests, OK

python tools/sync_cloud_training_artifacts.py ... --require-complete
[sync-ok] files=8 bytes=902177 mode=complete
```

首次真实同步发现云端非交互 `PATH` 没有 `python3`；工具随后加入 Conda 解释器自动
探测并重试成功。第一次失败发生在远端打包前，本地已有证据没有被覆盖。

目录事务的首版真实重同步还暴露了 Windows ACL 继承问题：将
`TemporaryDirectory` 内的 replacement 直接 rename 到目标后，普通工作区身份无法
读取。现场文件完整，已为 10k 目录恢复父 ACL 继承；实现随后改为在目标父目录创建
普通 sibling replacement。最终验收必须在提升权限同步之后，再由普通工作区进程
读取 manifest 和两张图片，不能只看同步进程退出码。
