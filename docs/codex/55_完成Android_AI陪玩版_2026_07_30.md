# 完成 Android AI 陪玩版

## 修改原因

训练阶段结束后，需要在不依赖 Ubuntu、Qt 或云服务器的前提下，把当前最优模型融入
一款可在 Android 上直接安装的《合成大西瓜》，并让 AI 投放在视觉上更接近人的
犹豫、试探和轻微手抖。

## 主要修改

- 新增纯 Windows Android Gradle 工程与项目本地 SDK 引导脚本。
- 导出 H256/L4 结构感知 GNN-Q 为动态 N/E 的五输入 ONNX，并用 24 个真实局面做
  PyTorch/ONNX 三路一致性门禁。
- 新增不依赖 pygame、pymunk、torch 的 Chaquopy 状态桥，继续复用训练时的完整
  `StateAnalyzer -> GraphBuilder`。
- 实现 560x1120 的 libGDX/Box2D 游戏、合成计分、队列、危险线、手动拖放、AI
  开关、动效和触觉反馈。
- Android 后台线程串行完成构图与 ONNX 推理；故障时回退本地安全启发式，不阻塞
  游戏。
- AI 只在稳定边界决策，拟人动画允许停顿、备选位置试探、回拉和不平滑轻颤，
  最终落点仍严格采用模型选择的 21 动作之一。

## 涉及文件

- `android/`：Android 工程、运行时、资源和 Windows 构建脚本。
- `src/daxigua_mobile/`：移动端纯 Python 图构建桥。
- `src/daxigua_rl/models/mobile_export.py`：ONNX 移动包装器。
- `tools/export_android_model.py`：可信 checkpoint 导出和一致性门禁。
- `tests/test_mobile_bridge.py`、`tests/test_mobile_model_export.py`：移动契约测试。
- `docs/mobile/ANDROID_APP.md`：构建、安装、模型更新和兼容边界。

- 移动桥与模型导出专项测试：10 项通过。
- 项目 Python 全量测试：402 项通过，1 项因 Windows 无符号链接权限跳过。
- 24 个真实局面的 ONNX argmax 一致率为 24/24，最大绝对误差为
  `0.0001220703125`。
- Android `assembleDebug`：49 个任务成功；Android Lint 报告
  `No issues found`。
- 最终 debug APK 为 `35,433,174` bytes，SHA-256 为
  `E694ED4FA426DE421C9601D498B7D886DC179A0A1E15C50C02D850D16407468E`。
- `aapt` 确认包名 `com.fruitmerge.ai`、minSdk 24、targetSdk 35、仅
  `arm64-v8a`；`apksigner` 确认 APK Signature Scheme v2 有效。
- 直接检查 APK ZIP 内容：ONNX 为 `13,828,110` bytes 且 SHA-256 与冻结值一致，

## 备注

首版只支持当前 `560x1120 / spawn_y=252 / 21 actions` 场景及 `arm64-v8a`。
移动端物理使用 Box2D，训练环境使用 Pymunk/Chipmunk；规则参数已映射，但不承诺
逐帧求解完全一致。当前电脑没有连接 ADB 设备，因此真机启动、触控手感和持续帧率
仍需把 APK 安装到手机后做一次体验验收。
