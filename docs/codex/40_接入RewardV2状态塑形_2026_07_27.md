# 接入 Reward V2 状态塑形

## 修改原因

静态 `StateAnalyzer` 已经能够计算 q0～q3 顶部可达容量、水果可恢复性和连锁
就绪度，但训练仍在使用存活奖励、最高堆叠高度、持续危险惩罚和固定 `-100`
终局惩罚。第一次大规模训练需要先把任务价值和局面质量改为设计规格中的 Reward V2，
同时保持 worker/episode/step 身份、truncated bootstrap 和并行采样语义一致。

## 主要修改

- 合成任务效用改为 `2**((new_level - 2) / 2)`；同一步多个真实
  `MergeEvent` 分别计值，不额外复制连锁奖励。
- 状态 potential 使用
  `capacity_weight*C + recoverability_weight*R + chain_readiness_weight*K`，默认
  权重为 `0.6 / 0.3 / 0.1`；shaping 使用与 DQN target 相同的 `gamma`：
  `lambda_phi * (gamma * Phi(next) - Phi(previous))`。
- 删除存活时间、最高水果高度和持续危险高度奖励。额外终局惩罚默认设为 0，只保留
  显式配置入口。
- `DaxiguaEnvConfig` 保存可 pickle 的 `StateAnalyzerConfig`，环境据此在 worker
  进程内创建 `StateAnalyzer`。collector 把动作前
  `TransitionKey` 传给环境；环境缓存正常 transition 的 next analysis，下一步直接
  复用，避免同一边界重复分析。
- terminal 强制 next potential 为 0 且不生成 next analysis；truncated 保存同
  episode 的降级 `analysis[t+1]`、next potential 和 DQN bootstrap，但 reset 后
  不跨 episode 复用。
- 完整 `StateAnalysis` 只通过 step `info` 留在 worker 内，不写入
  `TensorTransition`、冷热主 replay 或多进程返回载荷。
- `RolloutStats` 和并行统计新增 shaping 绝对值样本、StateAnalyzer 调用次数、
  耗时、缓存命中和降级数量；训练 CSV 记录 Reward V2 各分量、shaping p95、
  StateAnalyzer 性能与降级率。
- 训练 TOML 改为 Reward V2 参数；`tools/export_training_catalog.py` 同时识别
  新 task/potential 指标和历史 score/survival/height 指标，旧训练摘要继续可读。

## 涉及文件

- `src/daxigua_rl/reward.py`：Reward V2 配置、明细和纯计算函数。
- `src/daxigua_rl/env.py`：相邻状态分析缓存、轨迹键和 Reward V2 环境集成。
- `src/daxigua_rl/training/collector.py`：传递轨迹键并汇总 reward/分析统计。
- `src/daxigua_rl/training/parallel_collector.py`：跨 worker 合并轻量标量统计。
- `src/daxigua_rl/scripts/train_dqn.py`：Reward V2 参数、评估身份、CSV、终端日志和曲线。
- `src/daxigua_rl/scripts/compare_physics_modes.py`：兼容新版环境 reset/step 生命周期。
- `configs/train_dqn_fast30_parallel.toml`：正式训练 Reward V2 参数。
- `tests/test_reward_v2.py`：Reward V2 纯公式和身份契约测试。
- `tests/test_reward_v2_integration.py`：环境缓存、terminal/truncated、collector、
  并行统计和 spawn 集成测试。
- `tools/export_training_catalog.py`：Reward V2 与历史训练指标双兼容。
- `docs/rl/CAUSAL_ATTRIBUTION_V1.md`、`docs/rl/INTERFACE_V0.md` 及相关索引：
  更新实现状态和公开接口。

## 验证方式

在 `python-torch` 环境中执行：

```text
PYTHONPATH=src python -m unittest tests.test_reward_v2 -v
PYTHONPATH=src python -m unittest tests.test_reward_v2_integration -v
PYTHONPATH=src python -m unittest tests.test_training_metrics tests.test_training_catalog -v
PYTHONPATH=src python -m unittest discover -s tests -v
python -m py_compile tools/export_training_catalog.py
```

Reward V2 纯公式 13 项、环境/collector 集成 7 项测试均通过；训练指标、物理对比和
catalog 定向测试通过，全量回归共 90 项测试全部通过。catalog 另用历史 Reward V1
字段完成兼容探针，确认旧 `score_reward` / `survival_bonus` 指标仍可识别。

## 备注

- Reward V2 已直接进入 scalar DQN reward，但历史贡献归因尚未开始：
  `AttributionTracker`、pending 事件、`CausalReplayBuffer` 和规则 Q 排序仍是后续步骤。
- 当前 `TensorTransition` 格式没有增加完整分析对象，因此冷热 replay 的体积和
  Windows spawn 载荷不会因本步骤显著膨胀。
- 比较新旧实验时应以真实游戏 `score` 为主；shaped reward 的数值尺度已经改变，
  不能直接和历史 Reward V1 的 episode reward 横向比较。
