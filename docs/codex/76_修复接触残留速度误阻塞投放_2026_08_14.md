# 修复接触残留速度误阻塞投放

## 原因

稠密水果堆中，顺序冲量求解器会留下高频正负交替的线速度。水果在完整物理帧
求解后几乎没有圆心位移，但旧稳定判定直接读取瞬时 `vx/vy`，因此持续达不到
连续稳定窗口并耗尽投放等待预算。

## 修改

- Android、Tensor 参考后端和 CUDA 后端统一改为比较完整物理帧前后的圆心位移；
- 位移阈值仍为 `stable_velocity_epsilon / physics_fps`，等效保留 35 px/s；
- 继续要求角速度低于原阈值，并继续要求 15 个连续稳定帧；
- 不清零或篡改水果速度，后续碰撞仍使用真实动力学状态；
- 物理身份升级为 `tensor_cuda_v4_solved_motion_stability`，旧模型只能作为
  weights-only 来源，不能直接恢复优化器、Replay 或训练进度；
- 临时 Android 诊断面板独立保存在本地分支
  `codex/android-stability-motion-diagnostics`，不进入 `main`。

## 主要文件

- `android/core/src/main/java/com/fruitmerge/ai/game/FruitPhysicsWorld.java`
- `src/daxigua/simulator/vector.py`
- `src/daxigua/simulator/cuda/vector_step.cpp`
- `src/daxigua/simulator/cuda/vector_step_kernel.cu`

## 验证

实际执行结果：

- Tensor/CUDA物理、场景实验室和物理身份共56项回归通过；
- Android `:core:test`、桌面编译和Debug APK构建通过；
- 本地GPU使用正式无旁路`SAB-FF120 final.pt`作为固定greedy策略，执行
  64环境×250次投放，共16000次决策；
- 新规则仅7次真实等待超时，超时率0.0438%；L11出现后的3026次投放有2次超时，
  超时率0.0661%；
- 新规则已经稳定结束的15993次投放中，旧瞬时速度规则仍会阻塞3954次，占24.72%；
  L11出现后的旧规则误阻塞比例为47.09%；
- 第193至250次投放阶段，旧规则误阻塞率为52.56%，新规则实际超时率为0.0539%。
