# 实现轻量单帧堵塞风险数据与训练管线

## 原因

真实多帧堵塞检测器适合生成可靠离线标签，但不适合在大量反事实克隆分支中长期运行。
本阶段实现独立的数据生成和监督训练入口，把已确认的L7～L11同级水果对停滞事件转换为
轻量单帧风险监督。当前只准备新服务器上的数据采集、训练和独立评估，不接入Policy、
Replay、正在训练的新基线或反事实旁路。

## 标签语义

- SAB-128只负责在当前30 FPS、无快速自由落体环境中生成贪心真实对局；监督事实来自
  `PairFailureTracker`，不是SAB输出的蒸馏标签；
- 每个样本对应一个稳定决策状态中的同级L7～L11水果对；默认每4次投放稀疏记录一次；
- 正样本范围为已确认事件起点前24次投放至正式确认点，表示当前已经处于或未来24次
  投放内将进入最终确认的堵塞过程；
- 确认后仍持续堵塞的重复状态不作为负样本，也不继续大量复制为正样本；
- 没有匹配事件且拥有“预测24投放+确认24投放”完整未来覆盖的样本为负样本；未来覆盖
  不足的样本标记为截断并排除；
- 数据按完整`episode_id`固定划分训练/验证/测试，禁止同一对局相邻状态跨集合。

采集器不设置默认单局投放上限。全局事件目标、环境数、墙钟限制、稀疏间隔、设备传输
间隔和分片大小均可在服务器短测后调整。停止时在途对局会以采集器截断结束，其尾部未知
样本不会被错误标为负样本。

## 模型

`PairRiskModel`采用Pair-conditioned Deep Sets，不构建GNN图：

- 以目标水果对的预合成中心、结果半径和中心连线建立局部坐标；
- 共享小型MLP分别编码其他水果相对该坐标系的静态几何，再进行mean/max集合汇总；
- 配对静态几何、目标等级、集合摘要、水果队列和少量全局状态共同输出一个风险logit；
- 模型不读取瞬时速度或角速度，不包含动作探针、Q头或辅助动作效果头；
- 原始稀疏分片仍保存完整稳定状态和水果身份，后续更换轻量模型不需要重新跑真实对局。

默认结构为8维等级嵌入、48维集合编码和64维风险头。它们是训练入口参数，不是数据标签
或游戏规则；默认模型共13,281个可训练参数。训练使用带类别权重的二元交叉熵，并按
验证集Average Precision保存最佳checkpoint。

## 工具

数据采集并自动整理标签：

```powershell
python tools/generate_pair_risk_dataset.py collect `
  --output-dir runs/pair_risk_pilot `
  --device cuda `
  --parallel-envs 512 `
  --target-confirmed-events 1000
```

独立训练和测试集评估：

```powershell
python tools/train_pair_risk.py train runs/pair_risk_pilot `
  --output-dir runs/pair_risk_model_r1 `
  --device cuda
```

训练每轮原子更新`training_progress.json`，结束后保存`best.pt`和`evaluation.json`。当前尚未
把这组进度字段接入集成面板；服务器启动后先做环境数、分片和训练batch短测，再决定正式
参数。

## 验证与边界

- 交换目标水果顺序时输出不变，且模型梯度链路有效；
- 稀疏配对抽取只保留目标等级和目标投放间隔；
- 未来事件关联能区分正样本、完整未来负样本、确认后重复状态和未知尾部；
- 指标覆盖Average Precision、召回率、误报率、Brier分数、逐等级结果和事件提前预警；
- 合成8条样本的一轮CPU训练能够写出最佳checkpoint并完成验证/测试评估；
- `tests.test_pair_risk`、`tests.test_pair_failure`和`tests.test_rl_baseline`共47项通过；
- 本地CPU使用SAB-128完成1环境×4投放的采集、分片、结束记录和自动标签整理冒烟。

本阶段没有生成正式数据集，没有训练出具有效果证据的风险模型，也没有证明默认结构、
预测范围或阈值最优。CPU短跑和合成样本损失只能证明管线可运行，不能作为预测能力结论。
