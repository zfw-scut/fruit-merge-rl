# 恢复场景实验室直接操作手势

## 背景

场景实验室原生嵌入Xigua Atlas门户后，Python侧的实时物理、场景命令、模型预测和真实
评估API仍然保留，但旧页面中的直接操作状态机没有完整迁移。统一页面只能通过按钮完成
部分编辑，缺少“拖到松开即放置”等高频交互。

本次只恢复交互层，不重新引入已删除的自包含HTML，也不改变模拟器、奖励、模型结构、
checkpoint或训练数据契约。

## 实现范围

`portal/app/ScenarioWorkspace.tsx`新增统一指针手势状态机：

- 水果列表拖入画布与画布空白处拖放共用放置预览；
- 暂停场景直接拖动现有水果，松手后通过`load_scene`同步权威状态；
- 实时运行中按住水果后先发送`pause`，基于返回快照继续拖动，松手同步后发送`resume`；
- 右键删除、擦除工具、键盘删除和暂停状态触摸长按删除；
- 滚轮切换悬停水果等级或待投放等级；
- 选择、放置、擦除三种工具以及撤销、重做、取消快捷键；
- 指针捕获、单活动手势门禁、坐标提示和半透明水果预览。

`portal/app/globals.css`补充工具栏、指针模式、拖动状态、坐标标签和移动端布局样式。原有
模型预测、真实结果、空间诊断和显示设置仍由同一SVG画布分层绘制。

## 数据与状态边界

浏览器不在本地复制或推进物理。暂停编辑将当前`LiveState`序列化为场景快照，再使用现有
`POST /api/live/command`契约载入。实时投放继续使用`drop`命令；实时水果编辑通过一次
临时暂停避免与物理线程同时修改同一对象。

撤销栈最多保留80个暂停场景快照。撤销、重做不会回滚实时物理时间，也不会修改模型预测
缓存以外的训练或评估记录。场景变化后只使当前页面上的派生预测与真实评估结果失效。

## 旧实现审计

实现前按项目规则审计了`codex/work-1`。该分支没有可迁移的当前场景实验室前端；直接
操作证据来自本分支统一门户前一代已归档的场景页面。此次只提取交互语义并用React状态
机重写，没有恢复旧HTML运行依赖，也没有整批迁移历史代码。

## 验证

- `npm run lint`；
- `npm run build`；
- 场景实验室与门户服务单元测试；
- 在独立前端端口连接现有本地API，逐项验证拖入放置、暂停拖动、实时临时拖动、右键删除、
  滚轮换级、撤销和重做，并检查浏览器控制台错误。

这些验证只证明页面操作链路与API同步可用，不构成物理精度、辅助预测准确度或模型策略
效果提升的证据。
