# 解耦门户遥测与轻量场景查看

## 修改原因

门户此前把训练页绑定到单一`8765`来源和少数已知任务，把大量实时编辑、模型预测和图层
逻辑集中在`ScenarioWorkspace`。新增服务器或统计任务时需要同步修改启动器、代理和前端；
只想查看终局快照时也必须启动完整场景实验室。多次小功能改动因此跨越过多模块。

## 本轮边界

- 保留现有浅色Soft UI、RL训练曲线、Merge Potential专用视图和场景实验室交互；
- 不重写成熟的实时物理编辑画布，不改变模拟器、模型、Replay或训练契约；
- 新增通用任务快照，而不是继续为每种监督任务添加专用扫描器；
- 新增多来源聚合和显式实例启用，不把“登记的每台服务器”自动视为在线；
- 新增无服务的JSON场景查看页，并先让双环境静态对照复用只读画布。

## 实现

1. `TaskTelemetryPublisher`原子写入固定目录中的小型版本化快照，历史长度有界；扫描器不
   遍历任务数据、checkpoint或原始张量。堵塞风险采集和训练作为第一批生产者接入。
2. 本机实例登记增加`门户遥测`开关。启动器为所有启用实例建立独立回环端口，生成不含
   凭据的运行时来源注册表；门户并行读取，保留旧顶层`payload`作为兼容结果。
3. 实时训练页增加来源选择和通用任务卡片；原RL高密度曲线与Merge Potential继续按原
   契约显示，新任务无需再增加React专用面板。
4. 新增只读`SceneCanvas`、通用场景类型和`#scenes`快照查看页。查看器可读取单场景、数组
   或常见集合字段，不启动场景服务；实验室双环境静态画面已改为复用该画布。
5. 分析、训练、场景查看和场景实验室改为按页面动态加载；新增工作区样式进入独立
   `workspace-modules.css`，避免继续扩大旧全局样式职责。
6. 启动器登记自身PID；再次启动时只替换本工作区登记的整棵旧门户进程树，未登记端口仍
   保守拒绝终止，从根源上避免Python代理长期停留在旧代码版本。

## 验证

- `tests.test_task_telemetry`、`tests.test_telemetry_sources`、`tests.test_portal_service`、
  `tests.test_open_project_portal`和`tests.test_scenario_lab`共50项通过；最后一次门户专项复跑
  22项通过；
- `python -m py_compile`覆盖新增遥测、门户代理、启动器和首批生产者；
- `portal/npm run lint`通过；
- `portal/npm run build`通过，并生成按工作区拆分的动态前端chunk。
- 本地门户实机检查通过：`#scenes`可显示内置快照和图层开关；训练页能显示7号实例与
  本机产物两个来源；临时发布一个未知监督任务后，通用卡片自动显示70%进度、loss、
  macro AP和身份，清除临时快照后页面恢复；浏览器控制台无错误或警告。

本轮只证明结构契约、页面构建和只读显示入口成立，不构成模型效果或训练吞吐提升结论。
