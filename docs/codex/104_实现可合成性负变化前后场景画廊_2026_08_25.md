# 实现可合成性负变化前后场景画廊

## 修改原因

长期rollout已经得到4M条场景总体可合成值变化记录，但这些标量不能还原具体棋盘。为了判断
不同程度负变化通常对应怎样的一次投放干扰，需要补充约256组“投放前稳定场景 / 投放后稳定
场景”人工检查材料，同时保留以后重新渲染和调整分档的能力。

## 方案与边界

- 正式分布和第一版回查规格独立整理到
  `docs/design_specs/01_mergeability/08_长期变化分布与场景回查.md`；
- 按负变化幅度P50、P75和P95分成轻微、一般、严重、极端四档，每档目标64组；
- 候选只来自同局相邻两个稳定决策边界，终局重置边界无效，终局投放本身可以保留；
- 固定时长CUDA rollout中为每个候选生成随机优先级，只保留各档最高K项，避免取最早样本；
- 只在候选可能进入蓄水池时，把少量紧凑前后快照迁到CPU；完整批量的上一决策边界快照保持
  在GPU并原位更新；
- CUDA采集与Matplotlib渲染拆成两个工具。快照数据迁回后，本地只使用CPU生成图片；
- 图片记录动作、投放水果、合成事件、前后ID集合和可合成性贡献分解，但不把一步变化直接
  写成长期因果结论或检测器阈值。

## 本地验证

- Python编译通过；
- 分档边界、随机优先级蓄水池、紧凑快照和小型图片渲染测试通过；
- 合并原有可合成性、长期统计和静态场景测试后共15项通过，1项显式CUDA一致性用例因本机
  限制跳过；
- 本地没有运行CUDA rollout或大规模物理测试。

## 云端正式结果

- 12号实例CUDA冒烟通过后，以2000环境运行1000个批量决策步；
- 共观察2,000,000次投放和2337个自然终局，四档候选观察数分别为272,997、135,641、
  107,746和26,806；
- 随机优先级蓄水池四档各保留64组，共256组；状态为`complete`，无失败字段；
- 用时273.17秒，平均7,321.55次环境投放/秒；采集结束后GPU恢复空闲；
- 迁回的紧凑快照约4 MiB，本地CPU已生成256张成对图片、总览图、CSV索引和JSON报告；
- 本地目录为
  `runs/diagnostics/mergeability_negative_transitions_sab128_env2000_steps1000_20260825/`。

## 首轮读图结论

256组中215组发生至少一次合成，191组发生至少两次合成，82组发生至少四次合成。极端档
64组全部伴随合成，其中60组至少两次、44组至少四次；只有1组样本在投放后终局。严重档
仍有5组无合成样本，可用于单独观察纯几何重排。

这说明原始场景总量的负变化不仅包含“投放破坏了既有路径”，也包含正常合成时旧ID消失、
新ID创建、面积变化，以及整张定向递推图重新计算造成的持续水果分数变化。当前画廊达到了
暴露指标语义的目的，但不能把负变化分位数直接冻结成坏投放或关键事件阈值。完整解释边界和
逐档统计已写入`docs/design_specs/01_mergeability/08_长期变化分布与场景回查.md`。
