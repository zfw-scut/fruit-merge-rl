# 新增 CUDA 多环境并行模拟

> 语义更新：本文后半段的“物理稳定超时即 `truncated`”是当时的历史实现。
> 当前契约已将它改为非回合边界 `settle_timeout`，详见
> `07_将物理等待上限改为决策边界_2026_08_04.md`。

## 修改原因

accelerated-v1 需要为后续强化学习提供大规模并行数据采集能力。
旧分支 Pymunk 环境是单环境 CPU 实现，并行采集受制于 Python、进程通信
和每帧物理开销。本次以当前 `rules.py` 为权威规则，旧 Pymunk 实现
只作为物理行为参考。

## 确认的语义

- 合成计分、中点位置、前五级生成和西瓜相消来自当前规则；
- `MergeEvent.new_level` 和 `new_fruit_id` 在西瓜相消时为 `None`；
- CUDA 后端要求离散语义和大样本分布对齐，不要求与 Pymunk 逐帧、逐 bit 一致；
- 每环境使用可复现的设备端 LCG 状态，不复现 Python `random` 序列；
- 物理内核只输出客观事件和游戏分数，正式 RL 奖励必须通过插件显式提供；
- `terminated` 是危险线终局；技术 `truncated` 是回合边界；跑满单次物理等待
  上限仅返回 `settle_timeout`，不会结束或重置环境。

## 实现结构

- `src/daxigua/simulator/vector.py`：Tensor 状态、CPU 回退内核、批量 API 和 Python 兼容层；
- `src/daxigua/simulator/cuda/`：每环境一线程的整步融合 CUDA Kernel；
- `src/daxigua/simulator/reference.py`：按当前规则独立重建的 Pymunk 参考环境；
- `src/daxigua/simulator/reward.py`：可插拔奖励契约和非默认的游戏分数适配器；
- `benchmarks/benchmark_vector_simulator.py`：多步堆叠场景的稳态吞吐基准。
- `benchmarks/compare_reference_distribution.py`：强制相同动作/q0 流的 Pymunk/CUDA 分布门禁。

内部使用固定容量 SoA Tensor，结构状态全部常驻 GPU。CUDA 内核在一次
Kernel launch 内完成投放、所有物理帧、冲量解算、确定性无冲突合成、
连锁、稳定和终止，避免每帧 Python 调度和 CPU/GPU 同步。

## 性能设计

- 每个 CUDA 线程完整持有一个环境，环境之间无原子竞争；
- 对每环境只扫描活动槽位高水位，空场和少水果阶段不支付整个容量的二次成本；
- 普通合成复用较小的来源槽，投放复用第一个空槽，自然保持活动前缀紧凑；
- Tensor 观测默认是零拷贝短生命视图，只在进入 replay 等长期存储时显式 `clone()`；
- 容量耗尽会明确报错，不会为了吞吐删除水果或偷偷改变终止语义。

## 验证方向

- 标准规则、西瓜相消和可选事件字段；
- 批量环境隔离、局部重置、队列范围和固定种子复现；
- 确定性匹配、多对合成、跨帧连锁和西瓜不生成新水果；
- 稳定边界、等待超时、真实终止与技术截断分离；
- CUDA 固定种子重复运行完全一致；
- Pymunk 参考环境的当前计分、中点和合成半径契约。

## 2026-08-04 本机验证

验证环境为 RTX 4070 Laptop GPU、PyTorch 2.12.1+cu130，使用
`python-torch` 环境：

- 完整测试：28 项通过，包含 CPU 回退、CUDA 和 Pymunk 行为参考；
- 无 PyTorch 的默认 Python：11 项核心契约通过，17 项可选依赖测试按预期跳过；
- 统计门禁：64 环境乘 15 步，共 960 次转移；CUDA 相对 Pymunk 的得分、
  合并数和物理帧数误差分别为 9.91%、9.87% 和 4.02%，低于 15% 阈值；
  终止次数差为 0，截断次数差为 1；
- 4096 环境乘 20 步：约 72,586 环境步/秒、14,010,203 物理帧/秒，
  峰值 CUDA 状态显存 35.73 MiB；
- 4096 环境乘 100 步压力滚动：409,600 次转移，最高 33 个存活水果，
  所有位置和速度均为有限数值。

较长局面中，水果数量增加后确定性顺序冲量解算的二次复杂度会成为主瓶颈。
后续性能路线应优先评估保持统计语义的空间分桶或分阶段并行接触求解，而不是
减少求解帧数、修改稳定阈值或改变合并规则。

以上性能数字是同一机器、同一配置的单次结果，不作为跨机器承诺；可通过
`benchmarks/benchmark_vector_simulator.py` 重新测量。

## 4096 环境独立停止压力运行

为测试不同局长的环境并行退出，CUDA Kernel 增加了逐环境启用掩码，禁用行不会再
改变水果、队列、RNG、分数或计数。`benchmarks/run_random_until_stop.py` 使用该接口，
让每个环境随机投放，直到 `terminated`、`truncated` 或达到投放上限。

2026-08-04 使用默认 720 物理帧上限和 1000 次投放上限运行 4096 个环境：

- 模拟耗时 34.30 秒；包含已缓存扩展加载共 36.55 秒；
- 共执行 228,137 次完整投放和 41,715,047 个物理帧；
- 平均 6,652 环境步/秒、1,216,243 物理帧/秒；
- 投放次数均值 55.70，中位数 59，P90 为 83，P95 为 90，最大 140；
- 0 个危险线 `terminated`，0 个达到 1000 次上限；
- 4096 个环境全部先因连续稳定窗口未在 720 帧内满足而 `truncated`。

64 环境、每次最多 3600 物理帧的补充运行仍全部最终 `truncated`，说明这不是简单把
单次帧预算扩大五倍就能消除的问题。该结果应视为当前物理稳定性/接触求解的诊断证据，
不能把 `truncated` 改名为游戏失败，也不应为了得到更长局长擅自放宽规则阈值。

以上为修复前基线。后续已在不修改稳定阈值的前提下增加逐水果静止残余速度修正；
当前长局结果和剩余真实滚动边界见
`docs/codex/06_修正CUDA静止残余速度_2026_08_04.md`。
