# 让合成水果继承动量

> 历史记录：本页描述的动量继承规则已于2026-08-11被“合成水果创建瞬间线速度和
> 角速度均为0”的新规则覆盖。保留本文仅用于解释旧模型、旧回放与旧评估的物理身份；
> 当前规则见`53_合成水果初速度归零_2026_08_11.md`。

## 修改原因

此前 CPU、CUDA 和 Pymunk 参考实现都会把新合成水果的线速度和角速度清零，导致
来源水果的运动在合成瞬间凭空消失。按当前确认的物理语义，新水果应继承两颗来源
水果的动量。

## 当前语义

普通合成仍在两个来源圆心的算术中点生成新水果，等级、碰撞半径、质量和转动惯量
仍来自当前 `rules.py`。合成瞬间计算：

```text
P = m1 * v1 + m2 * v2
v_new = P / m_new

L = I1 * w1 + I2 * w2
    + cross(r1, m1 * v1) + cross(r2, m2 * v2)
w_new = L / I_new
```

其中 `r1`、`r2` 是两颗来源水果相对合成中点的位置。这样同时保留：

- 两颗水果的总线动量；
- 两颗水果自身旋转产生的角动量；
- 两颗水果绕合成中点运动产生的轨道角动量。

新水果的显示角度仍重置为 0，但角速度继承上述总角动量。两颗西瓜相消时没有目标
水果，因此不执行动量继承。

当前质量规则按水果等级半径取整，并不保证 `m_new = m1 + m2`。因此严格守恒动量时，
新速度不一定等于两颗来源速度的简单平均；目标质量小于来源质量之和时速度会相应
增大。这是当前质量规则和动量守恒共同决定的结果。本次不保证动能守恒，合成本身
仍可视为非弹性事件。

## 实现

- CUDA 融合 Kernel 在清除来源槽位前，使用碰撞求解后的速度和角速度计算继承值；
- Tensor CPU 后端对所有确定性无冲突合成对执行相同向量化公式；
- Pymunk 参考环境在 `post_solve` 合成回调中读取两颗来源刚体的当前动量并赋给新刚体；
- 合成位置、计分、ID、连锁次序、西瓜相消和奖励接口均未改变。

旧分支也会把新水果创建为静止状态，本次没有迁移旧实现。

## 验证

- CPU 精确测试验证合成前后的总线动量和关于中点的总角动量一致；
- Pymunk 参考测试验证相同守恒公式；
- CUDA 单物理帧测试验证融合 Kernel 输出预期继承速度；
- 原有确定性配对、连锁合成、西瓜相消和固定种子测试继续通过；
- 完整测试共 35 项通过；
- 4096 环境乘 20 步约 71,570 环境步/秒，全部状态为有限数值；
- 4096 环境乘 100 步压力测试完成 409,600 次转移，最高 58 个存活水果，
  所有位置、速度和旋转状态保持有限；
- 64 环境乘 15 步分布门禁中，得分、合并数和物理帧数相对误差分别约
  1.55%、3.06% 和 1.98%，等待超时次数差 5，门禁通过。
