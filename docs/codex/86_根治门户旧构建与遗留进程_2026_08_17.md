# 根治门户旧构建与遗留进程

## 修改原因

门户生产前端使用 Vinext 常驻进程。以前的启动器只判断3000端口是否已占用，
不校验运行中的构建是否与当前代码一致，因此前端更新后仍可能继续显示旧界面。
另一个原因是启动器保存的是 `npx.cmd` 包装进程 PID，而不是真正监听端口的
Node PID；只终止包装层会遗留旧 Node 进程。多次启动还可能创建重复的4312后端。

## 保留与调整

- 保留原有一体化启动命令、云端遥测隧道和工具进程白名单。
- 前端改为直接运行 Vinext Node 入口，登记 PID 与3000端口监听 PID 一致。
- 运行期间监测源码时间和生产构建身份；先完成构建，再替换旧前端。
- 前端意外退出时自动重启；构建失败时保留当前可用版本。
- 为前端写入本地运行时 PID 记录，下次启动会清理已登记的异常遗留进程。
- 4312端口已有门户API时直接复用，不再绑定第二个后端。
