# 增加长局终局抽样回放

## 修改原因

大规模随机长局的吞吐统计不能直接展示终局前物理行为，而在正式 4096 环境运行中
持续写逐帧追踪又会明显污染性能结果。需要在保留正式计时可信度的同时，抽取一组
可复现、可核验的长局回放。

## 实现

`benchmarks/run_random_until_stop.py` 新增可选的两阶段回放模式：

1. 正式阶段只运行融合 CUDA 模拟并记录汇总统计，不启用逐帧追踪；
2. 结束后使用固定种子均匀抽取环境；
3. 根据原环境索引恢复对应设备 RNG 初态，并重新生成与正式阶段完全相同的
   4096 维动作流；
4. 只用抽中环境确定性复跑，在终止或投放上限前连续若干次投放开启追踪；
5. 对每个样本核对局长、最终分数和结束类型，任何不一致都会终止导出；
6. 完整局模式输出 20 个独立 HTML、一个轻量索引页、每局完整 Tensor 追踪和
   JSON 清单。

这种方式不会把录像 Tensor 分配和写盘时间计入正式吞吐，也不依赖旧 Pymunk 分支。
`--replay-full-episodes` 会从第 1 次投放录到结束，每 2 个物理帧采样一次；短尾段
模式仍可通过 `--replay-tail-drops` 单独使用。

## 4096 环境正式结果

固定种子 `20260804`，每环境最多投放 1000 次：

- 4096 个环境全部因危险线正常终止，技术截断 0，达到投放上限 0；
- 最晚结束环境投放 318 次，因此整批在第 318 轮结束；
- 共完成 673,513 次投放和 94,683,099 个物理帧；
- 正式模拟耗时 108.31 秒，扩展加载 2.19 秒，总计 110.50 秒；
- 平均约 6,218 环境步/秒、874,184 物理帧/秒；
- 局长均值 164.43，中位数 161，P90 201.5，最短 101，最长 318；
- 分数均值 1239.13，中位数 1200，最低 488，最高 2957；
- 共出现 539 个等待超时间隔，涉及 510 个环境；这些环境均继续投放并最终正常失败；
- 峰值 CUDA 已分配显存约 37.76 MiB。

20 个抽样环境的局长、分数和终止类型均与正式阶段完全一致。最终交付改为完整局：
每条回放的投放段数与对应局长完全相等，不再只保留终局前 5 次投放。正式报告和
完整局回放清单位于：

- `recordings/random-4096-until-failure-or-1000-20260804.json`；
- `recordings/random-4096-full-episode-replays-20-20260804/manifest.json`。

## 验证

- 64 环境、20 次投放、3 条回放冒烟测试通过；
- 正式 4096 环境运行完成且无非有限状态或容量异常；
- 20 个复跑样本逐一通过局长、分数、终止类型一致性检查；
- 文件检查确认 20 个独立 HTML、组合 HTML、Tensor 追踪和清单全部存在；
- 完整局导出耗时约 257.4 秒，20 个 HTML 和 20 个 Tensor 轨迹均成功写出；
- 轻量索引页列出全部样本，避免一次加载所有长轨迹。

应用内浏览器自动化安全策略禁止直接导航到本地 `file://` 页面，因此本次无法自动
执行最终画布截图检查；该限制不影响用户直接打开本地 HTML。
