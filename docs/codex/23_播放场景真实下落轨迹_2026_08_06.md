# 播放场景真实下落轨迹

## 修改原因

此前场景实验室虽然会在松手后运行真实物理，但接口只返回最终状态。计算期间水果停在
释放点，随后直接跳到落点，用户看不到下落和碰撞过程；新水果也采用点击即放置，难以
在一次连续手势中精确定位。

## 本次修改

- 新增单场景 `settle_with_trace()` 诊断接口，在自然落稳时记录真实物理状态；原有
  `settle()` 和正式训练热路径不记录轨迹。
- `/api/settle` 返回初始帧、中间采样帧与最终帧。自动30 FPS整理逐帧采样，手动120 FPS
  整理每4帧采样，统一按约30次/秒传给浏览器。
- 前端按物理帧号和物理帧率播放轨迹，仅在线性插值相邻显示坐标；合成、消失、等级和
  最终落点均取自真实轨迹。
- 新水果交互改为鼠标按下拿起、按住移动、松手释放；已有水果继续使用相同拖动手势。
- 物理计算和轨迹播放期间显示分阶段中文状态，并阻止产生相互覆盖的场景编辑请求。

## 验证

- 模拟器契约测试覆盖初始帧、中间帧、最终帧、采样步长以及队列不变。
- 场景服务测试覆盖轨迹JSON、自动30 FPS采样和最终帧一致性。
- 前端文档测试覆盖轨迹播放器、按住放置状态与交互提示。
- 使用 `python-torch` 环境执行完整测试，90项全部通过。
- 在浏览器空白场景实测：按住水果移动后松手，页面先显示轨迹计算状态，随后显示真实物理
  轨迹播放百分比，并可在中间帧看到水果尚未到达地面。

## 性能边界

轨迹只由单环境场景实验室显式请求，不进入批量训练、Replay或21动作评估。120 FPS轨迹
下采样至约30次/秒传输，避免可视化功能影响正式训练吞吐。
