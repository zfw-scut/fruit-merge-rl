# 场景实验室双环境实时物理对照

## 目标

把物理后端与实际运行配置的差异检查变成场景实验室中的日常工具。修改碰撞、积分、稳定、
合成、CUDA ABI或物理参数后，无需另写脚本即可用同一场景、seed和动作直观看到两边轨迹，
同时保留数值差异和首次分歧帧。

## 实现

- 新增 `ScenarioLabComparisonSession`，在独立时钟中同步管理两个
  `TensorVectorSimulator` 世界，不进入训练热路径；
- 新增 `/api/comparison/state`、`/api/comparison/events` 和
  `/api/comparison/command`；
- 门户场景实验室增加普通模式/双环境模式切换、左右画布、预设切换、同步动作和差异面板；
- 差异按水果ID对齐，报告位置、速度、角度、角速度、分数、队列、等级和水果集合差异；
- 首次超过连续阈值或出现离散差异时冻结一份首次分歧记录，清空场景或切换预设时重置。

## 两个预设

### 后端一致性

- 左：Tensor/CPU；
- 右：CUDA Kernel；
- 两边均120 FPS、关闭自由落体快进、使用增量单帧入口和相同参数。

该预设用于发现Python/Tensor与CUDA实现漂移。开发机无CUDA时会显示CPU fallback，不能把
两条CPU路径一致写成后端一致性结论。

### 游玩与训练

- 左：当前场景实验室游玩配置，120 FPS、关闭快进、逐帧推进；
- 右：当时训练配置，30 FPS、开启快进、完整 `step()`。

训练侧完整执行投放后，用 `step_with_trace(frame_stride=1)` 返回的真实CUDA记录按30 FPS
语义帧在120 Hz对照时钟上回放。快进仅产生投放帧、快进落点和后续真实帧，因此界面明确
标记快进缺口，不对跳过的物理过程插值。

> 后续状态：`codex/71` 已将自由落体快进从当前 Python/Tensor 与 CUDA 物理域删除。
> 本节保留为对照工具建立时的历史事实；当前“游玩与训练”两侧都执行完整逐帧下落。

## 交互边界

- A0～A20“同步执行”才是训练完整步对照；
- 手工投放任意等级、拖动和删除同步修改两个世界，但属于调试场景，不代表训练动作；
- 训练trace播放完成前禁止继续投放，避免把尚未展示完的动作与下一次决策混在一起；
- 每次同步动作结束后自动停在两边相同的物理时刻；再次同步投放会自动恢复，端点差异不会
  被后续空闲帧覆盖；
- 加载checkpoint后支持模型持续决策：以左侧游玩状态推理，同一个greedy动作同步投放到
  两个环境，动作结束后自动继续，手工操作或任一环境终局时停止；
- 普通场景实验室、21动作验证和模型持续决策保持原行为。

## 验证

- 新增会话测试验证相同Tensor路径同步推进且差异为零；
- 新增HTTP契约测试验证对照状态和命令接口；
- CUDA测试验证训练侧返回41帧、其中快进27帧的trace，完整回放后自动停在可比较端点；
- Python全量140项测试通过；
- 门户 `npm run lint` 与 `npm run build` 通过。
- 浏览器验证两个预设切换、同步投放、快进缺口、首次分歧和Tensor/CUDA零差异显示，控制台
  无告警。
