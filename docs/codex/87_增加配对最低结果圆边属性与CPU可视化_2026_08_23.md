# 增加配对最低结果圆边属性与 CPU 可视化

## 修改原因

现有 Fruit Graph 能表达水果节点、相对几何、接触、运动碰撞候选和上下关系，但没有
显式描述一对水果沿当前方向最终完成合成后所形成的最低结果圆。为了给后续传统几何
“合成能力”预测提供通用输入，本阶段先增加结果位置和尺度表示，不加入堵塞规则、
预测器、奖励或策略规划器。

## 实现内容

水果物理边由 14 维扩展为 18 维，新增以下四项：

1. 配对最低结果圆的归一化中心横坐标；
2. 配对最低结果圆的归一化中心纵坐标；
3. 配对最低结果圆的归一化物理半径；
4. 结果圆是否存在。

中心位于两颗水果中心连线上，使用两者等级对应的标准半径按比例分割，并偏向较小
水果。同级时两者标准半径相等，中心自然退化为模拟器真实合成位置使用的圆心中点。
异级时，该中心描述较低等级水果沿当前方向成长并最终与较高等级水果合成时的最低
结果位置。

结果半径取两者较高等级再升一级后的合成物理半径。因此，同级配对对应真实的下一
等级结果；异级配对表示这对关系能够产生的最低结果尺度。若较高等级已经是 L11，
则不存在 L12，使用零半径和无结果标志表示最终消除。

该属性只对现有 Fruit Graph 邻居筛选后保留的边进入消息传递，未改变接触、近邻、
运动碰撞和纵向候选的选边规则，也不表达合成概率、时间或人工好坏判断。

## 兼容与运行方式

旧 checkpoint 的边编码器和边门控仍只有 14 维输入。查看或 weights-only 初始化时，
加载器会在新增四列上补零，再严格加载其余参数。这样旧 SAB-128 初始决策不读取新增
几何，同时后续训练仍可更新这四列权重。旧训练状态不得据此跨结构完整恢复优化器；
当前兼容入口限定为模型查看和 weights-only 初始化。

`capture_sab128_terminal_scenes.py` 新增 CPU 逐局路径。CUDA 模式继续使用批量掩码
步进；CPU 模式不调用只在 CUDA 后端提供的 `step_masked`，适合本机少量诊断，不建议
替代云端 256 环境批量评估。

新增 `visualize_pair_result_circles.py`：使用 SAB-128 在单个 CPU 环境中运行指定投放
次数，从实际保留的 Fruit Graph 无向边中固定随机抽样，并绘制水果连线、结果中心点和
结果半径虚线圆。绘图直接读取模型边张量中的新增四项，不另建一套几何计算。

## 实际验证

- `python-torch -m unittest tests.test_rl_baseline.ObservationAndModelTest`：
  6 项 CPU 测试通过，覆盖异级中心偏置、同级中点、下一等级半径、L11 无结果标志、
  模型有限输出和旧边权重补零。
- checkpoint round-trip 与 weights-only 初始化 2 项 CPU 测试通过。
- 修改文件 `py_compile` 通过，`git diff --check` 通过。
- 使用真实 SAB-128 checkpoint 完成 1 次投放的 CPU 终局画廊冒烟测试并生成 PNG。
- 固定种子 `20260823` 在单个 CPU 环境完成 100 次投放：得分 1058，场上 10 颗水果；
  实际保留 29 组无向 Fruit Graph 边，固定随机绘制其中 8 组，未提前终止。

本阶段没有运行 CUDA、大规模评估或训练。上述结果只证明几何语义、旧权重兼容和 CPU
诊断路径能够运行，不构成模型效果、训练吞吐或策略提升结论，因此不更新模型比较矩阵。
