# 统一 Git 提交语言与重写历史

## 修改原因

当前开发主线的近期提交说明大量使用英文前缀和英文正文。用户要求把现有 Git
历史中的自然语言说明统一为中文，并把“后续提交必须保持中文”固化为项目规范；
远程历史必须等待用户再次确认后才能强制更新。

## 主要修改

- 在改写前为 `main` 和 `codex/work-1` 分别创建本地备份标签。
- 自底向上重建 `codex/work-1` 可达的 90 个提交，并同步更新其中包含 47 个提交的
  `main`，保留两条分支的共同祖先关系和 2 个合并节点。
- 翻译 43 个含英文叙述的标题或正文，并规范 4 个旧提交说明；所有新标题均包含
  中文，不再保留 `feat:`、`fix:`、`docs:` 等英文前缀。
- 保留必要的 `AI`、`Android`、`CUDA`、`PyTorch`、类名和文件名等技术标识。
- 早期 11 个 GitHub 签名会因提交内容变化而失效，因此新对象移除了签名头；原始
  签名仍由本地备份标签保存。
- 新增 Git 管理规范，并把中文提交要求写入仓库级 agent 规则和文档入口。

## 验证方式

- 逐提交比较了旧备份与新历史：90 个提交的文件树、父节点数量与顺序、作者、
  提交者、邮箱、时间戳和时区全部一致。
- `main` / `codex/work-1` 的提交数分别保持为 47 / 90，合并提交数均保持为 2，
  且 `main` 仍是开发分支祖先。
- 文档修改前，两个备份标签与对应新分支的 `git diff --exit-code` 均无差异。
- `git fsck --full --no-progress` 返回成功；仅报告仓库在本次操作前已存在的不可达
  tree/blob，不影响引用完整性。
