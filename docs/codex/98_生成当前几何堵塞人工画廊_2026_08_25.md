# 生成当前几何堵塞人工画廊

## 修改原因

旧堵塞风险画廊围绕“未来24次投放内是否到达堵塞起点”组织预测帧、起点和确认帧三联图，
不适合验证`PB-GEO`的“当前帧是否已在堵塞事件区间内”语义。继续复用旧画廊会把当前检测
分数误读成未来预警概率，因此单独建立当前语义画廊。

## 实现

新增`tools/render_pair_blockage_gallery.py`：

- 只读取`blocked_now/pair_blockage_samples-*`和
  `pair_geometry_current_blockage_v1` checkpoint；
- 在冻结validation或test划分上批量推理，按L7～L11和TP/FP/FN/TN分组；
- TP/FN正例显示“起点前记录—经后续轨迹确认的起点—被分类的当前记录”三联对照；
  FP/TN没有真实事件起点，仍显示单个当前时刻；
- 三联图中每个可推理场景都单独输出`blocked-now score`，前置记录只提供历史布局对照，
  不表示未来风险预测；
- 高亮目标水果对，同时明确写出长期轨迹标签、模型判断、堵塞分数、阈值、episode、drop
  以及事件内相对位置；
- 正例按`event_id`去重，负例按episode与水果对去重，避免同一连续事件的相邻帧重复占满
  人工样本；
- 输出逐场景PNG、四类跨等级总览图和可复现`report.json`。

配套新增`tests/test_pair_blockage_gallery.py`，覆盖当前二分类语义、正负样本去重、前置记录
恢复和单帧/三联图渲染。

## 正式画廊

在10号实例使用正式冻结test划分、`PB-GEO`最佳checkpoint和统一0.5阈值生成：

- L7～L11 × TP/FP/FN/TN × 每类3张，共60张独立场景；
- TP、FP、FN、TN各一张跨等级总览图；
- 一份包含完整混淆计数和图片元数据的`report.json`。

工具先保留每个等级与混淆类型的候选事件，再从派生标签和原始曝光场景中恢复起点前最近
记录。405个正例候选中399个可恢复完整前后场景；最终渲染的30个TP/FN正例全部具有完整
起点前记录、完整目标水果对和可比较分数。13个样例的“起点”和“被分类帧”来自同一条
稀疏记录，图片显式标为`same record`，不是渲染未刷新。

画廊优先抽取每类高置信样本，目的是直接暴露模型最确信的正确判断、误报与漏检，不用于
估计自然分布。测试集0.5阈值的混淆计数与正式评估一致，例如L7为
TP/FP/FN/TN=`2246/19710/173/74185`，再次显示未经校准的统一阈值会产生大量L7误报。

图片约定：标题绿色表示判断正确、红色表示判断错误；目标水果对的红色边框表示长期轨迹
标签为“当前已堵塞”，绿色边框表示“当前未堵塞”。`blocked-now score`仍是排序分数，不能
当作已校准自然概率。

## 验证

- `python-torch -m unittest tests.test_pair_blockage_gallery tests.test_pair_blockage`：9项通过；
- 云端CUDA扫描208,030条正式测试样本并成功生成65个文件；
- 本地检查TP/FN三联总览，并抽查L11 FN、L7 TP独立图片；场地、水果尺寸、目标对、前置
  场景、起点、重复记录标记和信息栏均正常，图片中不再出现旧“未来多久到起点”含义。
