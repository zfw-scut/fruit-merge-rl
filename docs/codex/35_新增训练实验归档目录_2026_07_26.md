# 新增训练实验归档目录

## 修改原因

训练产物集中在被 Git 忽略的 `runs/`，其中 checkpoint、ReplayBuffer 和日志体积较大，无法直接随仓库迁移；但完全不记录又会让迁移后的开发者或 Agent 无法判断历史模型使用了哪些参数、训练到什么程度以及效果如何。因此新增一套轻量、可重复生成的实验目录。

## 主要修改

- 新增 `tools/export_training_catalog.py`，自动扫描标准训练目录并兼容项目现有的新旧指标格式。
- 新增 `docs/training_runs/`，生成跨实验索引和每次训练的摘要、配置快照、结构化指标及产物清单。
- 首次归档当前可识别的 9 次训练，并登记 CUDA 压力测试、物理模式对比、资源监控等辅助输出。
- 汇总真实单局得分分布、评估成绩、Reward Breakdown、训练性能、完成状态和本地数据体积。
- 对 `best.pt` 与 `latest.pt` 记录路径、体积和 SHA-256，但不复制 checkpoint、ReplayBuffer 或完整 CSV。
- 更新项目文档入口和文件职责索引，并增加归档工具自动化测试。

## 涉及文件

- `tools/export_training_catalog.py`：训练实验目录生成器。
- `tests/test_training_catalog.py`：生成器与统计逻辑测试。
- `docs/training_runs/`：当前训练实验的 Git 友好型摘要。
- `docs/README.md`：增加训练实验目录入口和阅读顺序。
- `docs/project_map/PROJECT_FILE_INDEX.md`：登记新增工具、测试和文档目录。

## 验证方式

- `python3 -m py_compile tools/export_training_catalog.py tests/test_training_catalog.py`
- `python3 -m unittest tests.test_training_catalog`
- `PYTHONPATH=src conda run --no-capture-output -n python-torch python -m unittest discover -s tests`
- 使用现有 `runs/` 实际导出 9 个训练目录，并复查总索引、长训摘要和归档体积。

## 备注

- 当前轻量归档约 200 KB，原始训练数据约 13 GB，二者职责明确分离。
- 迁移后只做历史分析时，Git 中的 `docs/training_runs/` 已经足够；观看模型仍需单独复制相应 checkpoint。
- 历史训练配置没有保存 Git commit，因此摘要会明确标记源码版本未知，避免给出无法验证的对应关系。
- 后续产生新训练后重新运行 `python tools/export_training_catalog.py`，并将更新后的摘要提交到 Git。
