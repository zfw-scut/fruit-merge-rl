# 新增持久化设置、历史与 AI 对战模式

## 修改原因

此前经典模式把人工和 AI 复用同一套“物理稳定后才能继续”的投放门控。这个限制
适合需要读取稳定图状态的模型，却会阻止玩家在上一颗水果下落途中拖动下一颗，
让手动操作明显慢于原游戏。

移动端同时缺少可调音量/震动、跨启动历史记录、正式对战规则和有停留过程的结算。
本轮在不修改训练模型、21 动作 ABI、水果贴图或基础 Box2D 参数的前提下补齐这些
产品层能力。

## 人工与 AI 投放门控

- `FruitMergeApplication` 将基础就绪、人工就绪和 AI 就绪拆成独立方法。
- 人工投放只检查游戏仍存活、下一颗已经出现且 `0.14s` 防误触冷却结束；不再
  检查 `physics.isStable()`、稳定窗口或上一组合成表现是否结束。
- AI 模式继续要求 `0.36s` 基础冷却、物理稳定、连续稳定窗口和分值表现释放，
  保证送入结构分析/ONNX 的仍是稳定边界。
- 上一颗投下后会立即推进并显示下一颗，拖动入口即刻开放；抬手时再校验投放
  冷却和人工门控，避免拖动期间页面、模式或游戏状态变化后误投。
- 人工连续投放期间发生的合成沿用当前活动分值序列；物理稳定后统一吸入 HUD，
  同时保留最大表现等待保护，避免玩家持续投放导致浮分永远不释放。

这不是降低 AI 的稳定要求，而是把“模型输入契约”和“人类操作节奏”从同一个
布尔条件中解耦。

## 持久化设置与历史

新增 `GameProfileStore`，使用 libGDX `Preferences` 文件
`fruit-merge-ai-profile-v1`。它只保存跨局数据，不保存当前 Box2D 世界或页面临时
状态；构造器也允许注入 `Preferences`，使核心逻辑无需 Android Activity 即可测试。

设置包括：

- 总音效音量；
- 合成、投放、收分三个震动触发点；
- 游戏速度；
- 对战每轮投放时限；
- 淘汰原因观察/结算停留时间。

默认仅开启合成震动，投放和收分不震动。音量、速度和时间会在读入及修改时执行
有限值检查与区间 clamp；恢复默认只影响设置。设置页每次修改都会 `flush()`，
不依赖应用正常退出才落盘。

历史包括：

- 总完成局数和历史最高分；
- 单局最多、累计合成大西瓜数；
- 对战胜、负、平；
- 对战最高分。

经典和对战在正式结束时各记录一次。读取时会修复负数和跨字段不变量，累计计数
采用饱和加法避免整数回绕。历史页的重置按钮需要二次确认，并且只清历史、不改
设置；设置页“恢复默认”也不会清历史。

## 设置与历史 UI

顶部新增记录按钮和齿轮按钮。两个浮层继续使用暖色果园的奶油底、圆角卡片、
薄荷开关和站酷快乐体，不引入 Android XML，也不改变 `560x1120` 逻辑坐标。

- 设置页使用统一的减号/当前值/加号步进控件和独立震动开关；
- 历史页显示六组汇总值，重置确认有短时视觉状态；
- 打开任一浮层会暂停当前经典/对战规则推进，关闭后从原局面继续；
- Windows 预览新增 `-Screen settings`、`history`、`duel` 直达入口，自动验收
  不需要模拟触摸命中。

字体生成器同步改为扫描 Android `core/app` 主 Java 源码中的字符串字面量，
跳过注释与字符常量，再与原有 ASCII/中文种子合并。当前共享 `1024x1024`
BitmapFont 包含 266 个 glyph，当前 Java 字符串缺字数为 0。

## AI 对战规则

新增纯规则控制器 `DuelMatch`。玩家和 AI 各自持有一个独立
`FruitPhysicsWorld`、分数、危险计时、步数和大西瓜计数，但每轮读取同一个当前
水果和同一条后续队列。

每轮规则如下：

1. 玩家与 AI 同时获得相同等级的待投水果。
2. 玩家可在截止前拖动并提交；AI 在自己场景稳定且时间充足时请求 ONNX 决策。
3. AI 场景尚未稳定、模型未就绪或时间不足时使用安全启发式；临近截止会取消
   拟人等待，直接落到规范动作列。
4. 截止时玩家仍未提交，则按玩家当前预览位置自动投放；AI 也有最终强制投放
   兜底，因此任意一方都不能跳过本轮水果。
5. 双方提交后等待很短的统一间隔，再只推进一次共享队列进入下一轮。

回合倒计时使用未缩放真实时间，改变游戏速度不会改变双方思考预算；Box2D、
合成和危险线则使用缩放后的时间。每帧始终先推进两边物理、消费两边合成，再在
同一边界判定淘汰，避免先更新一方产生规则优势。

一方水果持续越过警戒线即被淘汰。若双方同帧淘汰，则比较最终分数；同分允许
正式平局。`matchGeneration` 在重置时递增，异步返回的旧 AI 决策还要同时匹配
对局代次、轮次、待投等级和页面状态才可生效。

## 双场景表现与结算

对战画面保留一个完整前景场景，同时以对方阵营色绘制低透明、轻微错位的背景
虚影。右上角原 AI 开关在对战中改为“玩家前景/AI 前景”切换；顶部两张分数卡
分别使用淡红和淡蓝，并显示 `VS`。共享队列只画一份，前景方的预览、危险线、
爆浆和浮分保持完整可见。

淘汰发生后不立即盖住棋盘：

- 先停止规则推进并选择失败方为前景；
- 在可配置时间内显示淘汰原因和剩余观察时间；
- 观察期间仍允许切换前景，查看双方最终布局；
- 倒计时结束后再显示胜利、失败或平局页，并允许点击再战。

经典和对战结算均显示一个“已超越一定比例玩家”的整数提示。该值来自应用内的
单调平滑估计，仅用于本地成绩反馈，不联网、不采集样本，也不等同于真实排行榜；
UI 和面向玩家的文档不公开内部估计细节。

## 验证

- `:core:test`：成功；`DuelMatchTest` 6 项、`GameProfileStoreTest` 5 项，
  合计 11 项，失败和错误均为 0。
- 对战测试覆盖共享确定序列、双方单次提交、真实时间倒计时、超时投放、同帧
  胜负/平局、合成归属、大西瓜统计和 reset generation。
- 持久化测试覆盖默认震动、数值 clamp、内存 Preferences 重载、经典/对战历史、
  设置/历史独立重置，以及结算估计结果的有界和单调性质。
- `settings.png`、`history.png`、`duel.png` 已通过 Windows 共享渲染器生成，
  三张均为 `560x1120`；设置/历史卡片无文字干涉，对战图能同时辨识清晰前景与
  阵营色背景虚影。
- 字体生成器通过 Python 语法和 source cmap 门禁；`.fnt` 声明数与实际字符记录
  一致，当前 Java 字符串逐字检查无缺字。

## 边界

- AI 对战是同设备玩家对内置 AI，不包含联网匹配、账号或云同步。
- 设置和历史位于应用私有 Preferences；卸载应用或清除应用数据会删除记录。
- 对战双方共享随机水果序列，但仍使用两个独立 Box2D 求解器；跨场景不会发生
  碰撞或合成。
- 结算比例是体验型离线估计，不能用于宣称真实玩家分布。
