# 场景实验室接入水果对堵塞风险预测

## 修改原因

已经训练完成的轻量单帧水果对风险模型需要进入可直接观察的场景诊断流程，用于检查模型
是否能在真实布局中给出有意义的连续风险。第一版只服务人工观察，不进入Policy、Replay、
反事实行为段划分或物理控制。

## 新增与保留

- 新增`ScenarioPairRiskEvaluator`，从冻结checkpoint加载Pair-conditioned Deep Sets模型，
  把一个场景中的全部L7～L11同级水果对展开为一个CPU批次并返回连续概率。
- 场景实验室新增`POST /api/pair-risk/evaluate`和健康状态中的模型身份；未提供checkpoint时
  服务继续正常运行。
- 120 FPS场景中的水果年龄会按物理时间换算到checkpoint记录的30 FPS训练帧率，避免把
  `age_frames`直接放大四倍；危险进度、越线状态、队列和全场水果继续沿用训练输入语义。
- 门户显示设置新增“L7～L11 同级水果对堵塞风险”。稳定场景下约每0.5秒刷新一次；画布
  用绿—红虚线和中点百分比显示，悬停水果可查看各配对概率，右侧列出最高风险配对。
- 界面明确把概率解释为“未来24次投放内堵塞起始风险”，而非当前堵塞判定。模型输出不
  自动触发策略、事件或反事实逻辑。
- `tools/open_scenario_lab.py`默认在`runs/pair_risk/**/best.pt`和
  `runs/pair-risk/**/best.pt`中自动发现最新权重，风险设备默认CPU；门户工具参数允许单独
  选择风险推理设备。
- 真实权重及评估摘要从7号实例迁至
  `runs/pair_risk/model_50k_balanced_env5000_20260824/`，该目录保持Git忽略。`best.pt`
  大小为75,013字节，SHA-256为
  `3cc6ecb6e83b998c2317bb902df9218170720358935a33e5696428238f913a5e`。

## 验证

- `python -m unittest tests.test_scenario_lab`：28项通过；
- `python -m unittest tests.test_portal_service`：9项通过；
- `npm run lint`：通过；
- `npm run build`：通过；只有既有的大chunk提示；
- 用迁回的真实`best.pt`在CPU上请求一对L7水果，健康接口正确报告模型可用，响应读取
  24次投放预测窗口并返回一条配对概率；单次示例HTTP推理约4.6毫秒。
- 实际重启本地统一门户与场景实验室后完成浏览器验收：空场景会返回`0 对`而不会一直
  等待；装载一对稳定L7水果时，画布出现带百分比的配对虚线、两颗水果均有悬停说明，
  右侧摘要显示`1 对`及相同概率。本次真实模型CPU推理为3.78毫秒。
- 自动刷新依赖量化后的场景键，而不依赖每帧变化的SSE状态对象，避免高频实时状态更新
  反复取消260毫秒的预测定时任务。
