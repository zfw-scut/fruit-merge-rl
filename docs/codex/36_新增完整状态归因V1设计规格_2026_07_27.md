# 新增完整状态归因 V1 设计规格

## 修改原因

项目计划在较短开发周期内完成两到三次大规模训练，第一次正式长训就需要启用完整状态归因。
因此先冻结 Reward V2、状态分析、规则归因、因果 Q 排序和稀疏反事实的实现边界，避免后续
代码阶段出现重复方案或训练语义不一致。

## 主要修改

- 新增完整状态归因 V1 规格。
- 明确删除存活奖励和最高高度直接奖励，改用合成任务效用与状态 potential。
- 固定合成谱系、接触影响、支撑和可达图四类状态分析基础。
- 定义正负归因事件、待定/确认/撤销生命周期和埋死水果责任回溯。
- 确定使用独立因果回放直接约束现有 Q 值排序。
- 限制反事实成本，完整归因不依赖全量动作重演。
- 固定第一次大规模训练前的烟测、小跑和正式启用范围。
