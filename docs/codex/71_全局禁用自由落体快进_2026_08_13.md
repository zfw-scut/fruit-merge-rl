# 全局禁用自由落体快进

## 决策

自由落体快进退出当前物理域。训练、评估、回放、场景实验室、Python/Tensor 后端和 CUDA
后端都必须逐帧模拟新水果从投放点到首次接触的完整过程。

当前物理身份升级为 `tensor_cuda_v3_full_fall`。旧物理身份 checkpoint 不允许直接恢复训练；
模型权重仍可用于 weights-only 初始化和场景实验室演示，但不能把旧训练进度解释为当前物理域
下的连续实验。

## 原因与证据边界

同一 seed、动作和 30 FPS 参数下，完整训练 `step()` 与场景实验室逐帧入口可以逐位一致；
开启旧快进后，首次接触状态、后续碰撞与合成轨迹会发生明显分歧。该机制因此不是轨迹等价的
吞吐优化，不能继续作为训练默认值。

这是基于固定种子轨迹对照和场景实验室持续观察作出的物理规则决策，不是模型分数提升结论。
删除快进后的训练吞吐和策略质量需要在后续正式训练中分别测量。

## 实现

- 删除 `TensorVectorSimulator` 中投放前资格判断和首次接触预测跳帧；
- 删除 CUDA Kernel 中对应资格扫描、解析落点推进、跳帧 trace 和 ABI 参数；
- `training_fast()` 与兼容命名的 `high_fidelity_fast()` 都固定为完整逐帧下落；
- `drop_fast_forward` 只为旧配置和旧回放反序列化保留，传入 `true` 会归一化为 `false`；
- benchmark CLI 不再提供启用快进的参数；`fast_forwarded_frames` 结果字段为兼容监控保留，
  当前实现恒为 0；
- 双环境对照的训练侧仍使用完整 CUDA `step_with_trace()`，但 trace 不再出现快进缺口。

## 验证

- Python 回归验证旧 `drop_fast_forward=true` 无法开启跳帧；
- CUDA 扩展重新编译并验证训练预设的 `fast_forwarded_frames` 全为 0；
- 相同 30 FPS 配置继续验证 CUDA 完整步与场景实验室逐帧入口状态一致；
- 模拟器、训练配置和场景实验室测试覆盖物理身份、对照 profile 与完整逐帧 trace。
