# 实现单步旁路主动学习

## 修改原因

排名主动学习直接进入主轨迹时，低epsilon阶段约40%的投放可能持续破坏局面。在固定父
transition预算下，这既减少高质量正常对局，也让后续主动动作建立在已经被主动探索破坏的
状态上。本轮按已确认方案改为“单次动作克隆 + Replay隔离 + 扩大总模拟预算”。

本轮只实现采样和训练框架，不实现行为段反事实归因、长期分支环境或新的辅助标签。

## 固定算法语义

- 父轨迹保留24M transition，只使用原有epsilon随机与greedy动作；
- 额外预算为4M旁路transition，对应1M个父决策状态，约占全部父决策的4.17%；
- 旁路预算从6.4M父transition开始按累计目标释放；同一父决策批次不重复抽取状态；
- 父状态抽样使用独立设备RNG并保存其状态，不额外消耗父动作选择的随机数序列；
- 每个父状态复用actor已有的均值Q和多头分歧，按双排名得到候选，排除父动作后取前4项；
- 完整模拟器状态只在GPU内复制；每个克隆只执行一次投放，写入后不继续形成旁路对局；
- 4M旁路样本写入独立GPU Replay，不覆盖父Replay，也不改变父环境；
- 每次更新完整采样256条父样本，附加64条旁路样本；两路分别求loss均值；
- 总loss为`parent_loss + 0.25 * branch_loss`，旁路归一化有效权重约20%；
- 主动动作只保留价值名次与不确定性名次的窗口相关系数，不保存逐动作冗余诊断。

## 主要修改

- `src/daxigua/simulator/vector.py`：新增同设备批量模拟器行复制；
- `src/daxigua/rl/config.py`：新增可关闭的`BranchLearningConfig`及正式约束；
- `src/daxigua/rl/trainer.py`：新增累计预算调度、四动作单步克隆、独立Replay、进度和恢复；
- `src/daxigua/rl/learner.py`：一次联合前向中保留完整父batch，并附加独立加权旁路loss；
- `tools/preflight_training.py`：正式预检覆盖克隆、单步物理、标签、Replay和联合更新；
- `tools/train_gnn_dqn.py`：`--smoke`同步缩小旁路预算，保留完整端到端链路；
- `src/daxigua/rl/monitoring.py`、`src/daxigua/rl/curves.py`：展示旁路预算、Replay、吞吐和损失；
- `configs/gnn_dqn_auxiliary_action_l5_24m.toml`：关闭主轨迹主动分支，冻结24M+4M正式参数。

完整Replay继续不进入checkpoint。恢复时保留父/旁路累计预算；父Replay按原流程预热，
旁路Replay从恢复后的新旁路样本重建，并在至少达到一个旁路batch后恢复联合更新。该行为
避免临近训练末尾恢复时因达不到首次65K预热门槛而永久关闭旁路loss。

## 验证事实

- Python编译检查通过；
- CPU模拟器复制测试证明目标状态相等且源模拟器在旁路推进后不变；
- CPU learner测试通过父/旁路联合TD、bootstrap和辅助loss；
- CPU trainer端到端得到8条父transition、4条旁路transition和2个唯一父状态；
- RTX 4070 Laptop GPU上的同一CUDA端到端测试通过；
- 正式TOML的CUDA预检通过，覆盖双排名、GPU复制、单步物理、辅助标签、独立Replay、
  联合更新、checkpoint、曲线和30/120 FPS短评估；
- 预检按正式容量投影父/旁路Replay分别为4176478208/1044119552字节，合计约5.22GB；
- 正式训练入口`--smoke`正常结束：24条父transition、8条旁路transition、2个父状态，
  `run_status.json`为`completed`，旁路排名相关系数和两路loss均成功落盘。

这些结果只证明实现链路和资源规模可运行。单步旁路方案尚未做正式24M训练，不能据此
宣称策略得分、样本效率或高等级水果合成已经提高。
