# 场景实验室接入辅助动作预测验证

## 目标

让用户在自定义场景中先查看模型对某个投放动作的效果预测，再用同一场景、同一动作的
真实物理结果进行直观对照。主页面保留高频操作，低频显示选项集中到独立设置页。

## 实现事实

- `/api/model/evaluate` 从单次共享编码中同时取得21个Q值和21个动作的辅助效果预测；
- 展示适配层按训练标签的逆变换恢复坐标、速度、接触时间、得分和水果数变化；
- 场景评估模拟器开启动作事件跟踪，`/api/evaluate` 的每个动作新增真实
  `action_effect`，接口版本升为4；
- 模型预测和真实事实彼此独立，旧模型没有辅助头时只保留Q值功能；
- 画布可叠加首次接触位置与法向量、前三次新水果、q0最终后代及预测—真实误差线；
- 右侧结果区保留“预测+真实/仅预测/仅真实”的常用切换；
- 顶部齿轮打开独立设置页，集中管理图层、误差线、法向量、生成水果、q0后代、概率明细和
  自动选择模型动作，设置仅保存在浏览器本地，不进入训练配置。

## 性能边界

模型辅助预测复用已有动作表示，一次返回全部21个动作，不按动作循环前向。真实事实只在
用户主动发起的21动作场景评估中采集，不进入训练热路径；CUDA结果先整体复制到CPU后再
组装JSON，避免逐字段、逐动作触发设备同步。页面设置只控制绘制和文本密度，不会重新推理。

## 验证

- `python -m unittest tests.test_scenario_lab`：15项通过；
- CPU空场真实评估验证21个动作均返回动作效果事实；
- 小型辅助头模型验证一次返回21组可解码预测；
- 使用24M辅助动作checkpoint完成浏览器实测：先得到“仅预测”，随后执行真实评估切换为
  “已完成对照”，页面无控制台错误；
- 独立设置页已进行可见性、控件分组和关闭流程的视觉检查。

## 结论边界

本次证明预测数据能够在场景实验室中被正确解码、切换和对照，不证明辅助预测本身已经达到
新的精度水平。单场景像素误差是诊断样本，不应写成总体模型效果结论。
