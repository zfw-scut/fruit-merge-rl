# 实现 Reward V2 训练与可视化

## 修改原因

在保持第一版 GNN-DQN 模型和训练流程不变的前提下，需要把已确认的纯空间奖励落地，
形成可与纯分数基线直接比较的第二代训练流程，并让自定义场景能够解释奖励来源。

## 新增与保留

- 新增21列定长 Tensor 可投放空间、1～5级标准占用补偿表和队列对齐奖励。
- 正式训练使用相邻状态势能缓存；每步只分析新状态一次，终局势能归零，技术等待超时继续。
- 保留 `score_v1` 为显式基线配置，新增独立 `spatial_v2` 配置，不改变模型结构和1-step TD。
- 面板增加空间势能、变化、补偿、正负奖励率和几何耗时等低开销标量。
- 云端在选定环境数和 batch 后成对测量两种奖励；损失超过5%警告，超过8%阻止正式训练。
- 场景实验室通过本地服务并行执行21个真实动作，显示奖励分解、投放后局面和空间增减覆盖层。

## 验证

- 使用本机 Conda `python-torch` 环境运行87项完整测试，全部通过，其中包含 CPU/CUDA
  物理、Reward V2缓存与完整诊断一致性、终局边界和场景实验室21动作真实评估。
- 使用 RTX 4070 Laptop GPU 完成 CUDA 场景服务实测，返回21个动作和真实投放后局面。
- 内嵌前端脚本通过 Node `--check` 语法检查。
- 本地128环境、batch 64、6步、2次配对烟雾测试中，空间奖励中位端到端吞吐未低于
  分数奖励；该结果只验证门禁可运行，不替代 RTX 5090 正式规模的5%/8%判定。

## 旧分支边界

旧分支仅用于审计状态缓存和终局边界经验。本实现没有迁移15列CPU状态分析、网格BFS、
C/R/K potential、贡献归因、Shapley 或旧模型依赖。
