# 修正状态归因基础语义

## 修改原因

完整状态归因依赖可信的 episode 边界、真实碰撞几何和跨 worker 唯一的轨迹身份。
原实现会让 `truncated` transition 关闭 bootstrap，以显示半径代替碰撞半径，并且
无法区分不同 worker、episode 和 step 的历史动作。继续实现 `StateAnalysis` 会把这些
误差放大到可达性、封路和谱系归因中，因此先完成 V1 实现顺序的前两项。

## 主要修改

- 修正 `HeadlessGame.advance_physics()` 的稳定窗口判定：必须连续满足
  `stable_frames`，最后一帧瞬时静止不再漏报截断。
- 保持 `truncated` 为采集 episode 边界，但保留可信 `next_graph` 并允许 DQN
  bootstrap；只有真实 `terminated` 关闭 bootstrap。
- `FruitState` 和 `ActionCandidate` 新增真实物理半径，同时兼容旧构造参数。
- headless、可视化适配器、全局空间摘要和 GraphBuilder 几何统一读取实际碰撞半径；
  合法投放区间仍按显示半径计算，图特征维度不变。
- 新增 `TransitionKey(worker_id, episode_id, step_index)`。collector 在动作前生成键，
  并行 worker 使用固定 `worker_index`，多次 collect 调用间保持 episode 内连续。
- 主 `TensorTransition` 和冷热 `ReplayBuffer` 不加入归因字段；轨迹键通过
  `RolloutStats` 提供给后续独立的状态分析与因果回放链路。

## 验证方式

在 `python-torch` conda 环境中执行：

```text
PYTHONPATH=src python -m unittest tests.test_attribution_foundations -v
PYTHONPATH=src python -m unittest tests.test_graph_batch_training -v
PYTHONPATH=src python -m unittest discover -s tests -v
```

结果分别为 14、6、33 项测试全部通过，包含 Windows `spawn` 双 worker 回归。

## 备注

- truncated 的下一状态只供 TD bootstrap；collector 随后 reset，不会把未稳定局面继续
  当作同一 episode 投放。未来如果截断比例偏高，应实现环境内部无动作续推和硬异常上限。
- 同等级水果的物理半径可能因直接投放或合成生成而不同，后续 `StateAnalyzer` 必须读取
  `physics_radius`，不能根据 level 重算。
- 图维度没有变化，旧 checkpoint 仍能加载，但半径输入语义修正后会有轻微分布漂移。
- 下一部分从 `StateAnalysis` 只读 schema、15 动作可达性输入和诊断字段开始。
