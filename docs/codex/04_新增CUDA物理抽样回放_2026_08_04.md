# 新增 CUDA 物理抽样回放

## 目的

吞吐和统计分布无法替代肉眼物理审计。本功能允许从正在并行运行的 CUDA 环境中
抽取少量环境，记录一次或连续多次投放从生成到稳定、终止或截断的逐帧过程，用于发现穿透、
异常弹跳、滚动、堆叠、合并时机和稳定判断问题。旧分支观看脚本证明了渲染与训练
状态应解耦；本次没有迁移 pygame 或旧模型入口，而是直接记录当前 CUDA 后端状态。

## 设计

- `TensorVectorSimulator.step_with_trace()` 与普通 `step()` 使用同一个融合 Kernel；
- 通过长度为环境数的行映射，只让指定 CUDA 线程写追踪缓冲；
- 记录投放后的第 0 帧、固定间隔帧和最终帧；
- 保存位置、速度、角度、角速度、真实碰撞半径、等级、ID、活动状态、分数和累计合并数；
- 未开启追踪时传入不可访问的标量占位缓冲，不分配逐帧 Tensor；
- HTML 只负责离线绘制，不参与模拟，因此不会影响训练语义。

连续回放由录制器多次调用同一个逐帧接口，再按环境 ID 拼接为累计物理时间轴。
每条记录保留投放序号和动作；若某环境终止或截断，录制器正常批量重置，并在下一段
明确标记新局边界，不把重置伪装成连续物理运动。

`frame_stride=1` 可逐物理帧审计；普通观看建议设为 2，在 120 Hz 物理下生成
60 FPS 的回放。追踪对象可调用 `cpu()` 后通过 `torch.save` 长期保存。

## 使用

随机抽取环境：

```powershell
$python = 'C:\Users\yefan\miniconda3\envs\python-torch\python.exe'
& $python tools\record_cuda_replay.py `
    --num-envs 256 `
    --warmup-drops 4 `
    --record-drops 12 `
    --samples 3 `
    --frame-stride 2 `
    --seed 20260804
```

输出默认位于忽略提交的 `recordings/`：

- `cuda-physics-replay.html`：连续播放、暂停、逐帧、时间轴、投放序号、动作、样本和倍速切换；
- `cuda-physics-trace.pt`：按投放分段的完整 Tensor 追踪，便于后续数值诊断或重新渲染。

接入模型评估时，应先得到整批模型动作，再随机选择少量环境索引：

```python
result, trace = simulator.step_with_trace(
    model_actions,
    sampled_env_indices,
    frame_stride=2,
)
```

这样看到的是模型动作在当前 CUDA 物理上的真实执行过程，不需要切回 Pymunk。

## 验证

- 新增 CUDA 测试验证第 0 帧、间隔帧、最终帧和最终模拟器状态完全对应；
- 全量测试 30 项通过；
- 4096 环境、20 步且关闭追踪时复测约 72,906 环境步/秒，和修改前约
  72,586 环境步/秒处于同一波动范围；
- 固定种子抽取 3 个环境，各连续记录 12 次投放，共 1906 至 2568 个物理帧；
  三组累计合并得分为 30、36、77，过程中均未触发重置；
- 回放页经过 900×900 和响应式布局渲染检查。

当前回放以真实碰撞圆显示，不使用游戏贴图。这更适合检查物理边界，也避免贴图尺寸
掩盖碰撞半径；如后续需要观察模型整体策略，可在保持同一追踪数据的基础上增加
连续多次投放拼接和可选美术渲染。
