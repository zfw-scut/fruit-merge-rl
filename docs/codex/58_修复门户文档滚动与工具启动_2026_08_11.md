# 修复门户文档滚动与工具启动

## 1. 问题事实

浅色Soft UI外框增加了上下各22像素的窗口留白，但文档页仍按原整窗高度计算，底部被门户
外框裁切；左侧Flex文档索引也没有`min-height: 0`，浏览器无法把剩余空间分配给内部滚动
容器，表现为只能看到列表顶部。

门户启动场景实验室后进程以退出码1结束。日志明确显示
`ModuleNotFoundError: No module named 'daxigua'`：门户本身向`sys.path`加入了`src`，但启动
白名单子进程时没有把该路径写入子进程环境。问题与CUDA、场景模型或8769端口无关。

## 2. 修复

- 文档页高度扣除44像素Soft UI外框留白；
- 文档浏览器、列表和阅读器增加可收缩高度约束，索引列表独立纵向滚动；
- 移动布局继续使用自然页面高度，不引入嵌套滚动；
- 门户为所有白名单项目工具统一注入当前仓库`src`到`PYTHONPATH`；
- 工具异常退出时在卡片上直接显示最后一条错误摘要，同时保留完整日志折叠区；
- 子进程强制使用UTF-8输出，并区分用户手动停止与异常退出；
- 增加工具环境单元测试，避免后续再次依赖调用门户前的终端配置。

## 3. 边界

本次没有改变场景实验室、模型、物理或训练逻辑，只修正门户布局和子进程启动环境。
