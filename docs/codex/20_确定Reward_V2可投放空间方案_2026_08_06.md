# 确定 Reward V2 可投放空间方案

## 修改原因

纯分数基线无法区分“完成了同等分数的合成，但合成后空间结构不同”。
新奖励需要在不恢复旧分支重型状态分析的前提下，直接衡量未来水果
仍可使用的投放空间。

## 本次确认

- 建立独立 `reward-v2` 开发分支。
- 训练奖励改为纯空间变化与当前水果标准占用补偿，不混合游戏得分。
- 对 q1～q3 分别使用其自身的21个真实合法投放横坐标。
- 使用物理半径膨胀障碍、首次静态接触高度和梯形积分估计可投放面积。
- 严格对齐投放前旧 q1～q3 与投放后新 q0～q2，排除新随机 q3。
- 预计算1～5级当前水果与未来水果的25项标准空间占用补偿。
- 训练热路径只使用GPU定长张量和相邻状态缓存，性能下降目标不超过5%。
- 自定义场景和评估轨迹可保存完整21列诊断，训练主链只记录标量统计。

## 旧分支边界

已阅读旧分支 Reward V2 文档、`reward.py` 和 `StateAnalyzer`。保留其状态缓存与
边界语义经验，明确拒绝15列CPU分析、网格BFS、C/R/K potential、合成任务效用
和归因管线。当前实现不依赖旧分支文件或运行环境。
