# 实现高等级同级水果对长期停滞检测

## 原因

反事实贡献归因需要把“两颗高等级同级水果因空间关系长期无法合成”作为失败事件。
直接在大量克隆分支中执行长期多帧判断成本过高，因此先建立真实 rollout 使用的
轨迹标签检测器；后续再用这些标签训练单帧轻量风险网络。当前实现不进入 Policy，
也不替代真实长期 rollout 的最终因果判断。

## 检测语义

- L9～L11 为高等级：同级水果对身份持续不变、没有合成，且连续短窗口净位移很小；
- L7～L8 为较高等级：在上述条件之外，还要求两颗水果持续相邻；
- L1～L6 不检测；
- 只读取每次投放完成后的稳定圆心位置，不读取线速度、角速度或逐帧累计位移；
- 所有事件以水果对为单位，不建立同等级群体事件；
- 事件确认后回溯到候选条件首次开始成立的投放。

第一版待人工校准参数为：4投放净位移窗口、24投放确认窗口、最大净位移为水果
半径的0.12倍，L7～L8相邻表面间隙不超过较小半径的1.25倍。它们是标签生成参数，
不是游戏规则或模型输入常量。

## 实现

- 新增`PairFailureTracker`，复用64个固定水果槽位和模拟器原生`fruit_id`；
- 对固定2016个无序槽位对执行同形状CPU/CUDA张量更新，只用等级掩码筛选L7～L11；
- 每颗水果只保存很短的位置与身份环形历史，每对水果只保存相邻/候选连续时长、
  起点和确认状态；
- 合成、消失或槽位复用会改变`fruit_id`，候选自动结束，不需要Python谱系对象；
- CUDA热路径中不进行逐环境`.item()`或无条件主机同步，环境重置由采集器显式通知；
- 更新结果以固定张量给出开始、确认、结束、起点、持续长度、目标ID、净位移比例和
  表面间隙，便于后续批量筛选并建立单帧样本索引；
- 新增CPU人工验证工具，使用SAB-128与当前30 FPS无下落加速物理。每个事件以三联图
  保存候选起点前一次投放、候选起点和正式确认点；前置图仅表示当时尚未满足检测条件，
  不宣称几何上绝对没有堵塞。三帧按水果ID持续高亮同一对水果。工具也记录检测器耗时
  占比，供后续CUDA正式采集标定。

检测器没有接入训练器、Replay、Policy observation或反事实旁路。正常训练默认没有
新增运行成本。

## 验证

- 长期确认、起点回溯、净位移取消、往返运动不累计、L7～L8相邻约束、低等级忽略、
  身份变化结束事件等6项单元测试通过；
- 现有`tests.test_rl_baseline`共36项回归通过；
- 本地CPU使用4进程×4环境并行，总计16个环境；每个进程限制2个计算线程；
- 使用登记的SAB-128、当前30 FPS逐帧下落物理，16局×最多200投放，共3200次投放；
- 三联图版本总墙钟约724.0秒；16局都在诊断上限结束，因此本次不是自然终局效果评估；
- 共出现41个候选起点，其中30个在确认前解除，最终确认7例：L8四例、L9两例、L10一例；
  另有4个候选在200投放截断时仍未完成确认或解除；
- 7例确认事件均已生成“前置参考/候选起点/正式确认”三联图。前置参考严格取候选起点
  前一次投放，三帧按水果ID高亮同一目标。人工初查未发现快照错位或槽位复用误高亮；
  是否调整检测阈值等待进一步人工检查。

临时图片位于系统临时目录，不进入Git。当前结果只能说明检测语义和可视化链路工作，
不能说明轻量风险网络已经实现，也不能说明反事实训练或策略效果提升。
