# 重构纹理化长局回放

## 修改原因

早期回放以纯色碰撞圆为主，适合快速确认物理坐标，但存在几项长期使用痛点：

- 完整局需要真实水果外观，单看等级圆不容易判断视觉重叠和滚动是否自然；
- 20 条长局只能从索引逐个打开，浏览器会积累大量标签页；
- 长局按物理时间播放很慢，又缺少按投放和合成事件定位的入口；
- 观赏视图与碰撞半径、速度、ID 等调试信息无法独立开关；
- 每帧 JSON 重复字段名，未压缩 HTML 和稀疏 Tensor 归档占用大量磁盘；
- 修改播放器后只能重新运行 CUDA 录制，不能直接复用已有 `.pt` 追踪。

## 资源与规则边界

当前分支从项目共同基线中有选择地复用了 `assets/fruits/01.png` 到 `11.png`。这些图片
已经被旧 Python 表现层和 Android 成品按相同等级使用；本次没有复制旧渲染代码，也不
依赖 `codex/work-1`、旧工作树或旧运行路径。

回放严格区分两种半径：

- 贴图尺寸来自当前 `rules.py` 的显示半径；
- 可选白色碰撞圈来自逐帧追踪中的真实物理半径。

纹理、播放速度和智能浏览都只影响观看方式，不改变位置、速度、角度、合成、奖励或
终止语义。

## 新增与重构内容

### 单局播放器

`src/daxigua/simulator/replay_web.py` 集中维护浏览器模板，数据转换继续留在
`replay.py`。播放器新增：

- 11 级透明水果贴图，并随追踪角度旋转；
- 智能浏览、真实物理时间、逐次投放总览三种模式；
- 上一/下一投放、上一/下一合成和投放下拉定位；
- 贴图、物理圈与角度、线速度向量、水果 ID/等级独立开关；
- 键盘逐帧、逐投放、合成事件和首尾跳转；
- 对稳定、等待上限、失败、技术截断和重置边界的明确状态说明。

### 数据体积

公开的 `trace_to_payload()` 默认仍返回带字段名的记录，避免破坏现有调试调用。HTML
写入器内部使用固定数组记录，随后把状态 JSON gzip 压缩并以内嵌 Base64 数据块保存。
浏览器通过原生 `DecompressionStream` 解压，回放仍是单文件、可移动、可脱机打开。

追踪归档新增 `save_trace_archive()` 和 `load_trace_archive()`：`.pt.gz` 使用快速 gzip，
载入固定使用 PyTorch `weights_only` 安全模式。旧格式 3 的 `.pt` 仍能读取，新写入归档
版本为 4。

### 多局目录与重新渲染

`write_replay_catalog()` 生成带筛选、排序、前后切换和 iframe 的单页目录。任意时刻只
加载当前一局，保留每局独立 HTML 的可移植性，也不再要求打开大量浏览器标签页。

新增 `tools/render_replay_trace.py`。它可以把一个或多个已有 `.pt`/`.pt.gz` 直接渲染为
新版 HTML 和目录，无需重新运行 CUDA。旧浏览器可显式使用
`--no-payload-compression` 生成未压缩状态数据。

`tools/record_cuda_replay.py`、`benchmarks/run_random_until_stop.py` 和
`benchmarks/diagnose_truncated_motion.py` 已改用压缩追踪归档；未启用回放时，模拟器
热路径和 CUDA 吞吐不受影响。

## 主要文件

- `assets/fruits/`：11 级透明 PNG 与资源说明；
- `src/daxigua/simulator/replay.py`：追踪转换、纹理内嵌、压缩归档和目录 API；
- `src/daxigua/simulator/replay_web.py`：单局播放器与多局目录模板；
- `tools/render_replay_trace.py`：已有追踪重新渲染入口；
- `tools/record_cuda_replay.py`：新录制默认保存 `.pt.gz`；
- `benchmarks/run_random_until_stop.py`：完整局目录和压缩归档接线；
- `benchmarks/diagnose_truncated_motion.py`：诊断追踪统一为可重新渲染的压缩归档；
- `tests/test_replay.py`：回放格式、资源、归档和目录测试。

## 实际验证

- `python-torch -m unittest tests.test_replay -v`：7 项通过；
- `python-torch -m unittest discover -s tests -v`：完整 42 项通过；
- Node.js `--check`：播放器与目录脚本语法通过；
- 真实 CUDA 单投放 smoke：生成 44 条采样记录和 `.pt.gz`，Node.js 使用与浏览器相同的
  `DecompressionStream` 成功还原 1 个环境、1 次投放的紧凑数据；
- 旧环境 787 的 230 次投放、30260 物理帧追踪成功直接重新渲染；
- 该 HTML 从 `20,661,439` 字节降到 `6,249,989` 字节，减少 `69.75%`；
- 20 条真实完整局全部重新渲染，HTML 总大小从 `306.81 MiB` 降到 `94.26 MiB`，
  减少 `69.28%`，目录包含 20 个按需加载链接；
- 环境 1003 的原始追踪从 `64.95 MiB` 压缩到 `3.83 MiB`，减少 `94.10%`；
- 新生成的 20 条验证回放位于 `recordings/replay-v2-momentum-full-episodes-20-20260804/`，
  该运行产物继续由 Git 忽略，不进入源码提交。
