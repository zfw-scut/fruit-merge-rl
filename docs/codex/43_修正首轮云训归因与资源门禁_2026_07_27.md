# 修正首轮云训归因与资源门禁

## 修改原因

云端第一次正式 5k 烟测完成后，训练数值和资源生命周期正常，但暴露出三类放大训练前
必须修正的问题：

- 普通高优先级反事实持续占满 10% 共享硬预算，使已被 selector 选中的局部 Shapley
  长期得不到 token；
- Shapley 关闭时会清空未执行任务，却没有形成可审计终态；
- 少量原动作复现失败只有总数，没有保存原因；checkpoint/replay 写入产生的文件页缓存
  也会让 cgroup 原始内存余量产生误导。

## 主要修改

- 在 10% 共享硬预算内，为局部 Shapley 固定保留 1%；普通反事实仍以 6% 为软预算，
  高优先级任务最多借用到 9%。
- Shapley 区分真正提交、runner 完成/失败和 selected 后未执行的 terminal drop。
  readiness 同时检查结果闭环与终态闭环，terminal drop 只能解释去向，不能冒充有效样本。
- 反事实 coordinator 有界保留最近 32 条轻量失败记录，并聚合 failure reason、
  diagnostic code 和 trigger reason；完整快照、上下文图和模型载荷不会进入记录。
- readiness 允许已分类、未生成标签的物理复现失败由独立 1% 失败率门槛判定，但
  executor/runner、pending、孤儿/重复结果、标签转换和 replay 写入错误始终阻断扩容。
- cold replay 改用原子写入；只有保存成功才推进 segment index。正常训练结束先 flush
  最后冷段再保存 final checkpoint，消除 checkpoint 索引落后磁盘一段的问题。
- Linux 在大文件 `fsync` 后以 best-effort `POSIX_FADV_DONTNEED` 提示回收一次性写缓存；
  新增 cgroup-v2 旁路监控，分别记录原始余量、`inactive_file` 和可回收工作集余量。

## 涉及文件

- `src/daxigua_rl/attribution/counterfactual.py`：外部 token 保留份额及调度统计。
- `src/daxigua_rl/training/local_shapley_coordinator.py`：真实提交与 selected 终态账本。
- `src/daxigua_rl/training/counterfactual_coordinator.py`：有界失败诊断记录和聚合。
- `src/daxigua_rl/training/checkpointing.py`、`replay_buffer.py`：原子 cold segment、
  页缓存提示和落盘守恒。
- `src/daxigua_rl/scripts/train_dqn.py`：配置入口、指标与最终 flush 顺序。
- `tools/check_training_readiness.py`、`tools/preflight_training.py`：新配置契约和阶段门禁。
- `tools/monitor_cgroup_memory.py`：cgroup-v2 工作集与 memory event 监控。
- `configs/train_dqn_fast30_parallel.toml`：正式 1% Shapley 保留份额。
- `docs/rl/CAUSAL_ATTRIBUTION_V1.md`、`FIRST_500K_RUNBOOK.md`：冻结后的语义和操作手册。

## 验证方式

本地 `python-torch` 环境执行：

```text
PYTHONPATH=src:tests python -m unittest discover -s tests -p "test_*.py"
python -m py_compile <本轮修改的 Python 文件>
git diff --check
```

结果为 297 项测试全部通过，语法检查与 diff whitespace 检查通过。云端同提交的全量
测试、正式 preflight 和新的 5k/10k 运行证据将在部署后补入唯一 readiness 记录。

## 备注

- 原 5k 的 4 次失败产物没有保存细粒度原因，历史上只能证明 runner 正常返回且原动作
  复现门拒绝；不能事后猜测具体 mismatch 类型。新运行会直接保留原因。
- 本轮没有提高 Shapley 选择率，也没有放宽 1% 反事实复现失败率或 10% 共享硬预算。
- 500k 正式训练仍需新的 5k、10k 和最终云端 preflight 全部通过后才能启动。
