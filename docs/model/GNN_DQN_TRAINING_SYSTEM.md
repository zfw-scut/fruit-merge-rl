# 第一版 GNN-DQN 训练、性能标定与云端运行规格

- 状态：第一版基线训练系统已确认
- 实现：模型、trainer、隔离评估、面板、性能标定和分析产物已完成本机轻量验证；
  RTX 5090 的最终规模与吞吐等待云端实测
- 目标：在单张 RTX 5090 上同时完成基线训练、端到端性能上限测量和可审计产物归档
- 边界：本页只规定第一版基线；战略模型、FiLM、高层计划和 BMCTS 不进入本轮训练

## 1. 物理与评估边界

正式训练的环境采集、Replay、TD target 和优化器更新全部只使用修复后的 30 FPS
`SimulatorConfig.training_fast()`。120 FPS 状态不得写入 Replay，也不得参与任何训练
loss，只用于隔离的 greedy 评估。

同一 checkpoint 使用固定且独立于训练、并在两种帧率间配对一致的种子，分别运行
30 FPS 和 120 FPS 评估，比较
分数、局长、最高等级、合成、动作分布、危险状态和最终水果数量。训练局滚动均分包含
epsilon 探索，只用于运行观察；正式模型比较以独立 greedy 评估为准。

建议评估节奏：

| 项目 | 频率 |
| --- | --- |
| 30 FPS 训练局滚动统计 | 每 10～30 秒汇总 |
| 30 FPS greedy 评估 | 每约 2M～5M transition |
| 120 FPS greedy 评估 | 10M、25M、50M、100M 等里程碑及最终阶段 |
| 最终评估 | 30 FPS 与 120 FPS 各 4096 局 |

评估使用 `inference_mode()`、`epsilon=0`，不修改训练环境、Replay、网络或优化器。评估、
checkpoint 和 profiler 窗口不计入正式训练吞吐。

## 2. 固定学习语义

| 项目 | 第一版固定值 |
| --- | --- |
| 算法 | 1-step Dueling Double DQN |
| 奖励 | `score_delta / 66` |
| 折扣 | `gamma = 0.99` |
| 损失 | Huber，`delta = 1.0` |
| 优化器 | Adam；CUDA 支持时使用 fused kernel |
| 学习率 | 固定 `1e-4` |
| Adam | `betas=(0.9, 0.999)`、`eps=1e-8`、无权重衰减 |
| 梯度裁剪 | 全局范数 10 |
| Target 更新 | 每 1000 次 optimizer update 硬同步 |
| UTD | learner sampled transitions / collected transitions = 1.0 |
| Replay 采样 | 均匀采样，不使用 prioritized replay |
| Epsilon | 预计正式 transition 前 40% 线性 `1.0 → 0.05`，之后保持 `0.05` |
| 复现边界 | 固定种子和完整身份记录；不为 bit 级确定性关闭高吞吐 CUDA 路径 |

恢复训练沿用原始 epsilon horizon，不重新提高已经下降的探索率。正式训练开始后不得自动
修改 batch、学习率、UTD、Replay 规则、Target 周期、模型结构或物理参数。

## 3. Replay

Replay 使用预分配 GPU 环形缓冲，只保存重建模型输入所需的最小原始状态，不保存图对象
或已经编码的图。连续位置、速度和物理半径保留 FP32；同级水果的投放半径与合成半径并
不相同，因此物理半径不能只由等级重建。等级、队列、年龄和掩码使用紧凑整数或布尔
类型；质量、数量和其它可确定派生量不重复存储。
每条 transition 另外保存一个紧凑阶段标签，仅用于预热配额、监控和离线分层分析，不
进入模型输入或 TD 目标。

容量规则为：

```text
capacity = min(2,097,152, max(1,048,576, 256 * num_envs))
```

正式 checkpoint 默认不保存完整 Replay，避免数 GiB 设备数据频繁阻塞训练。异常恢复时
加载模型、Target、优化器、调度进度和 RNG，再显式重建 Replay，并在恢复记录中标记。

## 4. 分阶段预热

预热量为 Replay 容量的 25%。先用随机策略短跑得到当前物理下的投放数分位点，再给各
环境分配不同的真实预投放长度。预投放必须经过真实 CUDA 物理，禁止只修改计数器。

预热样本按实际状态进入分层 reservoir：

| 阶段 | 配额 |
| --- | ---: |
| 初期 | 30% |
| 发展期 | 30% |
| 拥挤期 | 25% |
| 危险期 | 15% |

危险阶段优先依据 `danger_progress` 和当前越线标志。投放数和阶段标签只用于采样与监控，
不作为模型输入。预热结束后恢复普通在线收集和均匀 Replay。

## 5. 性能上限标定

首轮云端运行既是训练，也是正式性能测量。容量候选依次为：

```text
1024 → 2048 → 4096 → 8192 → 16384 → 必要时 32768
```

每档在独立子进程中测试纯物理、构图与 Actor、Learner，以及 UTD=1 的完整管线。测试
必须使用混合阶段局面，不能只测空场。1024 是调试档，4096 是首个正式候选，但最终以
端到端 transition/s 决定。

满足 OOM、显存超过 85%、连续两次翻倍增益低于 10%，或 Learner 已完全限制吞吐时，
停止继续扩大。分别保存最大安全规模、纯物理峰值和端到端最佳规模。

Learner batch 测试 `256/512/1024/2048`，第一候选为 512。更大 batch 只有在样本吞吐
提高至少 15%、数值稳定且保留足够显存时采用。精度依次比较 FP32+TF32、BF16，以及
BF16+`torch.compile`；编译模式只有在无 graph break 且端到端提升至少 10% 时启用。
选中配置再用独立子进程生成一个短 Chrome Trace；该 profiler 结果不参与吞吐选择。

## 6. 训练期资源扩容

模拟器按标定出的最大安全环境数预分配，用 `step_masked` 控制当前活跃环境。排除评估、
保存和 profiler 窗口后，连续 120 秒同时满足 GPU 低于 80%、CPU 低于 75%、显存低于
80% 且没有 I/O 或同步阻塞时，测试下一环境档位。新增环境先完成真实阶段预滚动。

新档运行约 120 秒；端到端吞吐提高至少 8% 才保留，提升不足则回退，下降超过 5% 或
显存超过 85% 时立即回退。两次调整至少间隔 10 分钟。允许调整活跃环境数、Actor 推理
分块和不改变数值语义的流水线调度，不允许借自动扩容修改学习算法。

CPU 占用低本身不是问题：当 GPU 已高负载且端到端吞吐接近峰值时，CPU 空闲是预期
状态。只有 GPU 与 CPU 都低且吞吐不足时，才优先扩大批量或排查同步空洞。

## 7. 热路径与 CPU 边界

模型、图构建、Replay、物理和 learner 全部驻留 GPU。第一版不增加 CPU rollout worker、
CPU 图构建或多进程 Actor RPC，避免恢复旧分支的 IPC、小实际 batch 和资源句柄问题。

CPU 只承担低优先级旁路任务：监控面板、NVML、日志、checkpoint 写入、哈希、产物压缩、
抽样轨迹导出和 watchdog。建议使用 2～4 个核心。训练热路径禁止逐步 `.item()`、CPU
复制、打印、绘图、逐帧录制和无必要的 CUDA 同步。

## 8. 实时训练面板

训练主进程通过非阻塞有界队列发送紧凑指标快照，独立低优先级进程负责资源采样、持久
日志和只读 Web 面板。队列满时允许丢弃旧监控样本，面板失败不得阻塞或终止训练。

面板绑定 `127.0.0.1`，通过 SSH 端口转发访问。GPU 指标使用 NVML，不通过高频
`nvidia-smi` 子进程采样。

| 数据 | 建议刷新 |
| --- | ---: |
| transition、update、epsilon、Replay、吞吐和当前阶段 | 1 秒 |
| GPU/CPU/内存/功耗/温度/时钟 | 2 秒 |
| TD、Q、target、reward 和梯度聚合 | 10 秒 |
| 训练局分数、局长、合成和动作统计 | 30 秒 |
| greedy 分数 | 只在正式评估完成后更新 |
| profiler | 标定或异常时短时启用 |

面板至少展示总进度、ETA、投放和更新速度、各管线耗时、GPU/CPU/显存/内存、Replay、
训练损失、Q 值、梯度、动作分布、训练局滚动指标、30/120 FPS 评估、checkpoint 与告警。

## 9. 时间预算与产物

云端启动先执行编译、正确性门禁和性能标定，随后根据实测端到端吞吐与租用截止时间
冻结预计 transition 总量。正式训练使用较高上限，以租用截止时间减去至少 30 分钟的
最终评估和打包窗口作为主要停止边界。

至少保存 1M、5M、10M、25M、50M、100M transition 里程碑，便于后续模型按相同样本
量比较。`latest` 每约 30 分钟原子更新，`best` 由 120 FPS greedy 平均原始分数决定，
正常结束写入 `final`。

关闭服务器前必须带回模型 checkpoint、冻结配置、代码与硬件身份、性能标定、训练和
评估指标、资源日志、短 profiler、分层 transition 样本、完整决策边界轨迹和 SHA-256
清单。默认不传完整 Replay。只有本地核对传输哈希后才释放服务器。

## 10. 停止门禁

NaN/Inf、CUDA OOM/Xid、Replay 损坏、水果容量耗尽、checkpoint 验证失败、计数倒退、
连续无进度、磁盘不足或非有限物理状态均触发安全停止。长期吞吐下降、settle timeout
异常、持续降频、显存过高或梯度异常触发告警和一次短 profiler，不允许监控自身反复
打断训练。
