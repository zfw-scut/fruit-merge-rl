# 第一版 GNN-DQN 基线设计

- 状态：模型、1-step TD、奖励与第一版训练系统均已确认
- 目标：建立后续所有模型升级共同对比的最小 GNN-DQN 参考版本
- 实现状态：已完成首轮基线与后续传播扩容；本文保留最小参考规格，最新模型排序见
  `../model_evaluations/COMPARISON_MATRIX.md`

## 1. 基线边界

第一版不是无结构 MLP，也不迁移旧分支完整训练栈。它保留对象图、动作节点读出、
edge-conditioned 消息传递、Dueling 与 Double DQN 等主干思想，并使用当前批量 Tensor
状态和 CUDA 物理重新实现。

基线删除旧分支中的 StateAnalysis、chain motif、规则动作排序、causal replay、反事实
物理、局部 Shapley、贡献归因、结构辅助损失和 Reward V2 潜势塑形。

## 2. 最小模型

| 部分 | 第一版内容 |
| --- | --- |
| 场上对象 | 最多 64 个物理水果节点 |
| 可见队列 | q0～q3 队列节点 |
| 物理边界 | 左墙、右墙、地面节点 |
| 全局状态 | 一个全局聚合表示，包含危险进度和越线标志 |
| 动作 | 21 个对应真实 `drop_x` 的单向动作探针 |
| 图编码 | 节点/边编码器、混合局部水果图、edge-conditioned 消息传递 |
| Q 读出 | 全局状态价值 `V(s)`、动作优势 `A(s,a)`、Dueling 合成 |

水果物理边、动作探针单向消息、两级动作聚合和状态取舍遵循
`ACTION_CONDITIONED_EFFECT_VIEW.md`。基线不启用计划嵌入或 FiLM。

基线按以下顺序传递消息：

1. 水果通过混合局部边互相传播，并与左墙、右墙、地面交换物理消息；
2. q0～q3 在独立队列小图中编码顺序；
3. 水果、队列和 `danger_progress` 单向汇入全局节点；
4. 水果、队列和全局上下文单向汇入 21 个动作探针；
5. 全局节点只用于状态价值，动作探针只用于动作优势。

全局节点不回写水果，动作探针没有出边，动作之间不传递消息，动作也不回写全局节点。
这样保持 `V(s)` 与动作无关，并隔离 21 个互斥动作假设。

## 3. 强化学习目标

基线使用 1-step Dueling Double DQN：

```text
a* = argmax_a Q_online(s_next, a)
target = reward + gamma * Q_target(s_next, a*)
```

正式终局不 bootstrap。`settle_timeout` 不是终局，保留下一状态并继续 bootstrap。基线
不使用 3-step 或其它 n-step 回报，不需要每环境多步回报累积器。

训练主链保留 target network、Huber TD loss、梯度裁剪、epsilon-greedy、固定容量
replay、独立 greedy 评估和 checkpoint。

### 3.1 第一版模型尺寸

| 参数 | 第一版固定值 |
| --- | ---: |
| 水果与物理边隐藏维度 | 128 |
| 物理消息传递层数 | 3 |
| 队列隐藏维度 | 64 |
| 队列消息传递层数 | 1 |
| 全局表示维度 | 128 |
| 动作探针表示维度 | 128 |
| 每个动作的精细水果数量 | 8 |
| 激活函数 | SiLU |
| 归一化 | 每层残差后 LayerNorm |
| Dropout | 0 |
| Value/Advantage 头 | `128 → 128 → 1` |

q0～q3 建立 12 条有向顺序边。全局水果聚合同时使用 sum、max 和有效水果数量，避免
平均聚合丢失数量。动作探针保留全水果轻量扫描，并只对 8 个关键水果执行完整精细
消息。

首轮训练不搜索结构超参数。基线稳定后再分别比较隐藏维度 64/128/256、物理层数
2/3/4 和精细水果数量 4/8/12。

## 4. 基线奖励

```text
rl_reward = score_delta / 66
```

`score_delta` 是当前一次投放区间内全部真实合成的游戏分数增量。固定线性缩放不改变
动作间的最优关系，只控制 TD 数值尺度。

基线奖励不包含存活奖励、步奖励、终局额外惩罚、高度或危险塑形、水果数量、合并机会、
合并债务、区域结构、反事实贡献、非线性等级效用或奖励裁剪。训练日志必须分别记录
原始 `game_score` 和缩放后的 `rl_reward`，模型比较以固定 greedy 评估的原始游戏指标
为主。

初始折扣方向为 `gamma = 0.99`，是否进行折扣消融留到基线稳定后。

## 5. 不进入第一版的模块

- 战略 Pair Encoder 及 1/4/16/64 步预测；
- 等级节点、区域锚点、合并机会和合并债务网络；
- 动作效果辅助任务；
- FiLM、高层规划器和可行性网络；
- prioritized replay；
- BMCTS 和搜索蒸馏。

## 6. 训练系统

第一版使用 GPU Replay、UTD=1、Adam、线性 epsilon、硬 Target 同步和 30 FPS 独占训练。
120 FPS 只用于隔离评估，不产生训练数据。并行环境、Learner batch、BF16 和编译模式在
正式训练前通过端到端性能标定选择；训练期只允许调整不改变学习语义的执行规模。

完整参数、阶段预热、资源扩容、实时面板、评估、checkpoint 和云端产物规则见
`GNN_DQN_TRAINING_SYSTEM.md`。

## 7. Baseline Scale V1传播深度实验

Reward V2与V2.1均未达到分数基线后，本轮恢复`score_v1`，只扩大基础物理GNN传播深度，
不引入空间奖励、辅助任务、高层计划或新状态量。5层候选未通过RTX 5090性能门禁，按预案
回退为4层正式配置：

| 项目 | 历史基线 | 5层候选 | 4层正式模型 |
| --- | ---: | ---: | ---: |
| 物理消息传递层数 | 3 | 5 | 4 |
| 水果/物理边隐藏维度 | 128 | 128 | 128 |
| 队列隐藏维度 | 64 | 64 | 64 |
| 可训练参数 | 725,423 | 1,028,045 | 876,734 |
| 环境数 / batch | 1856 / 1792 | 1792 / 1792门禁 | 1792 / 768 |
| 奖励 | `score_v1` | `score_v1` | `score_v1` |

5层门禁相对3层吞吐下降27.8%，正式显存投影35,079.5 MB，未通过15%吞吐和85%显存线。
4层、batch 768的门禁吞吐下降11.5%，显存投影25,703.5 MB，通过门禁。正式训练完成
16.001M transition、20,493次更新和54,469局，4096局评估的30/120 FPS局均分为
3742.69/3471.08，相对历史基线提高14.10%/13.68%。

`baseline-scale-v1-l4-r1`因此成为当前效果基准，完整证据见
`../model_evaluations/model-baseline-scale-v1-l4-r1.md`。由于batch、环境数和实际训练量同时
变化，本轮确认的是4层正式配置整体更优，不能把全部增益严格归因于传播层数。只有保持
单变量边界后，才继续比较隐藏维度128→160或其它模块。
