# 战略区域锚点算法设计

- 状态：已确认的算法方向，尚未进入实现
- 适用范围：新模型战略视角中的空间聚合与高层计划定位
- 非目标：本页不规定软归属函数、网络尺寸、张量布局或计划类型全集

## 1. 目的

战略层既要理解材料位于什么位置，又不需要承担 21 个投放动作的精确物理判断。区域
表示因此需要提供稳定、粗粒度、可跨时间记忆的横向空间语义，并避免硬分区切断水果
之间原本连续的几何关系。

## 2. 七个固定横向锚点

第一版战略图设置 7 个从左到右排列的固定横向区域锚点。锚点身份在相邻决策步之间
保持不变，使 GNN-GRU 可以持续记忆“当前计划针对哪个区域”，并能稳定比较各区域的
材料、空间和危险变化。

7 个锚点是第一版默认值，不作为永久超参数。模型稳定后需要对 5、7、9 个锚点进行
消融比较，判断战略分辨率、学习难度和计算成本之间的平衡。

## 3. 软归属而非硬分区

水果不被互斥地划入单一区域。靠近边界、横跨较宽范围或半径较大的水果，可以同时向
相邻的多个区域锚点传递消息。这样可以避免水果轻微移动后区域身份突然跳变，也不会
人为切断跨区域的同级水果对和可联通关系。

区域锚点表达的是一段横向空间的战略状态，不等同于固定碰撞格、精确投放坐标或不可
穿越的边界。

## 4. 垂直方向作为区域摘要

第一版不额外创建顶部、中部和底部区域节点。垂直结构作为每个横向锚点内部的摘要，
用于表达该区域的高度分布、顶部压力、底层材料、空隙和危险趋势。

这与游戏的控制方式一致：模型直接选择的是横向投放位置，投放后的纵向位置由真实
物理过程决定。完整二维区域网格会增加大量固定节点，却不能给高层提供同等程度的
直接控制能力。

## 5. 与其它战略节点的分工

| 节点 | 主要职责 |
| --- | --- |
| 水果个体节点 | 保留具体水果、位置、运动、危险和 pair 关系 |
| 等级节点 | 聚合同级材料、理论进位、合并机会和合并债务 |
| 区域锚点 | 聚合某段横向空间的材料布局、纵向摘要、空间结构和局部风险 |

同一信息可以通过不同关系影响多个聚合节点。例如一对跨区域的同级水果既影响对应等级
节点，也会按软归属影响相邻区域，从而同时保留“它们是什么材料”和“它们在哪里”。

## 6. 为高层计划提供位置语义

高层计划选择一个区域、相邻区域范围或与其关联的目标结构，不直接指定 21 个动作中的
精确投放点。低层执行器在计划条件化后，负责选择能够实现该战略意图的具体动作。

目前已经确认区域表示需要支持至少两类计划需求：

- 在指定区域构造较大水果，以合成、带动或解除快要出界水果造成的危险；
- 在通往底层的狭窄缺口附近构造合适的大水果，降低后续小水果掉入缝隙并被长期隔离的
  风险。

这些例子说明高层计划需要描述希望改变的局面结果，而不只是“合成某个等级”。计划的
正式类型、目标对象、成功条件和持续方式将在显式计划设计中单独确定。

## 7. 验证原则

后续需要验证：

- 软归属能否避免边界附近水果产生不连续的战略表示；
- 区域表示能否识别材料集中、顶部压力、底层缝隙和局部合并债务；
- 高层计划能否稳定引用同一区域并观察计划进展；
- 5、7、9 个锚点对规划质量、训练稳定性和推理成本的影响；
- 仅使用水果节点、加入区域锚点、再加入垂直摘要后的逐项消融。

## 8. 推迟到实现阶段的内容

以下内容尚未冻结：

- 区域摘要的具体通道和聚合算子；
- 跨区域 pair 消息的传递方式；
- 高层区域范围如何编码；
- 区域锚点与 21 个动作位置之间的映射；
- 缝隙、通道等临时结构是否形成独立的计划候选实体。
